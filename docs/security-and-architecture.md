# Relayune 架构与安全约束

本文是强制约束。修改 Server、Relay、登录授权、加密或凭据存储前阅读；参数及禁止事项不得因精简根说明而省略。

## 唯一生产架构

- Server 只采用自托管 MongoDB 版本。不得重新引入 MariaDB、MySQL、D1、R2、
  Cloudflare Worker、Sites 运行时或本地明文 broker。
- Nginx 提供 `dist/self-hosted/` 静态文件，并把 API 反向代理到只监听
  `127.0.0.1:3192` 的 `dist/self-hosted-server/server.cjs`。
- MongoDB 只监听 `127.0.0.1:27017`。运行时必须使用独立最小权限账户，禁止使用
  MongoDB 管理员账户。
- 大型加密响应写入私有 blob 目录，MongoDB 只保存不透明路径。不得把 blob 目录
  暴露为静态目录。
- macOS / Windows Relay 的控制通道使用 HTTPS 主动出站长轮询，Server 不反向连接电脑。
  支持时在同一命令请求内等待最多 20 秒，命令持久化后由服务端唤醒并立即返回密文；
  响应后 Relay 立即续接，旧服务器保持 750ms 轮询。等待提示只存在单进程内存，不保存业务载荷；
  MongoDB 仍是持久 HTTPS 命令和租约的唯一依据，唤醒后重新鉴权，断开和停服释放等待。
  协商 `online-stream-v1` 后，另建主动出站 `/api/stream` WSS 通道转发在线密文事件、
  只读命令、响应与目录变化，不逐条落库。人工写命令继续采用持久 HTTPS 队列。
  每客户端独立授权及 A256GCM 不变；10 秒业务续租、30 秒租约、30 秒权限复核及
  45 秒授权新鲜度共同约束连接。订阅快照过期必须停止生成接收方副本，不能回退为
  离线事件入库；结束/待处理通知保留受限的低频投递。每端 64 条/256 KiB 未确认额度，
  10 秒无消费进展暂停并要求历史恢复。连接代次绑定路由及加密回执；详见
  [在线投递与容量](online-relay-capacity.md)。
  手机响应读取可协商最长 10 秒的 HTTPS 等待；等待前及唤醒后验证设备归属和独立
  客户端授权，按授权与请求编号隔离唤醒，最多每授权 8 个、每服务进程 2048 个等待。
  响应持久化后直接返回既有密文，等待中不保存载荷，客户端断开和停服释放等待。
  已授权手机可选择 WebRTC DataChannel 传输会话命令、审批、实时事件、历史和附件。
  登录、授权快照、设备目录发现与握手仍经服务器；握手通过既有 `transport.offer` /
  `transport.answer` 密文请求响应交换，SDP 与 ICE 地址不进入明文服务端字段或日志。
  保持独立客户端 PAKE 与 A256GCM envelope，不新增明文 broker。新版以 `webrtc-trickle-v1` 能力启用渐进 ICE，候选批次仍封装在 `transport.offer` /
  `transport.answer` 的认证密文内，绑定原始 connection_id、客户端及密钥；限制候选数量与大小，
  旧连接候选不得注入新连接。不具备该能力时沿用完整 SDP 交换。协商能力为
  `webrtc-session-v2`，DataChannel 标签为 `relayune-session-v2`；旧只读能力不表示支持写操作。
  直连接收方仅接受显式会话命令和传输控制白名单，验证身份、AAD 路由、请求编号及有效期。
  撤销授权、控制通道失效或授权快照超过 45 秒时关闭直连。仅使用 STUN，不配置 TURN。
  两条链路共用写操作执行记录：执行前持久化客户端身份、命令摘要和过期时间，最多保留
  1000 条未过期记录；恢复用响应仅保存已加密 envelope，合计上限 16 MiB，超过时改走 HTTPS。
  写操作回退须保留原始请求编号、AAD 和密文，禁止换编号盲目重试。进程崩溃后不能确定
  是否执行的请求不自动重做；不能把这项去重保证描述为跨 Agent 的事务性 exactly-once。
  实时事件先写入现有加密 outbox；收到对应客户端的加密 event_id/event_seq 确认后仅删除
  该接收方副本，其他客户端不受影响。直连失败或事件实际发送后 10 秒未确认时回退原密文，客户端按
  event_id 去重。切换前暂停新事件的下发，排空旧 HTTPS 上传，手机补齐服务器事件后
  激活直连。主动切回服务器、App 暂停或撤销配对时关闭本客户端直连。
  自动模式另要求加密能力 `webrtc-auto-v1`，验证加密 nonce 回应、同步屏障和激活确认后
  才使用直连。探测与确认仅经对应 DataChannel，不允许通过 HTTPS 伪装成直连验证成功。
  探测绑定当前客户端密钥、设备、请求编号与连接实例；旧连接完成不得激活或关闭新连接。
  前台空闲时每 15 秒探测，4 秒无响应则回退；失败退避并带随机延迟，后台停止探测。


## 端到端加密不变量

账户认证有两种显式部署模式：官方邮箱模式，以及不依赖 SMTP 的自托管用户名模式。
两种模式使用独立数据库；本地用户名映射到不可变 `acct_…` 账户 ID，不能伪装为已验证邮箱。
自托管唯一所有者通过部署机器本地命令或受限初始化令牌创建，不能由首个公网访问者抢占。
初始化依赖 MongoDB 唯一约束，重启不覆盖账户；密码只保存 scrypt 摘要，不内置通用密码。
本地恢复通过账户认证代次立即拒绝旧会话，并在 WebSocket 复核和 HTTP 长轮询唤醒时重新鉴权；
已经独立批准的 Desktop 与客户端配对仍按现有模型显式撤销，不因改密码而复用或导出其内容密钥。

服务选择必须先进行无凭据、禁止重定向的实例探测。Desktop/Mobile 切换实例时停止旧链路、
清理或隔离旧凭据与加密缓存、拒绝延迟旧操作写入新状态，然后重新登录与配对。
Web 凭据和内容密钥仅用于页面同源 API，拒绝公共构建参数指向其他源以及远程明文 HTTP。
实例私有 CA 只能在用户核对指纹后明确受信；Mobile 的 CA 仅绑定所选实例，Desktop/Web 使用系统信任。
不得添加全局无效证书回调；证书有效期、签名、主机名仍须检查。

- 会话数据仅在浏览器、原生客户端和本机 Desktop Relay 解密；用户主动反馈按文末规则
  直接保存为可读字段。Server 可以校验鉴权和路由元数据，
  但不得接收、记录、持久化或推导短码、PAKE 中间密钥、最终内容密钥或会话业务明文。
- 会话业务载荷只持久化严格的 `A256GCM` envelope 及其经过认证的路由元数据。
- 每个浏览器或移动客户端的首次授权使用 8 位短码和 RFC 9382
  `SPAKE2-P256-SHA256-HKDF-HMAC` PAKE。短码只显示在桌面端，
  不得进入 URL、API 请求、MongoDB、日志、分析事件或错误上报。
- 客户端授权 URL 只携带随机配对编号。macOS Web 登录回跳 URL 只携带随机登录请求编号，
  不得携带设备令牌、轮询秘密、连接码或其他凭据。配对和桌面登录会话必须一次性使用、
  10 分钟失效。配对时 Server 只保存双方公开 share、双向确认值、状态和必要路由信息；
  桌面登录只保存轮询秘密摘要、设备令牌摘要、账户确认状态和必要路由信息。
- 8 位短码必须以 scrypt（N=32768、r=8、p=1、40 字节输出）和配对编号盐值映射为
  P-256 标量。SPAKE2 必须使用 RFC 9382 固定 M/N、65 字节 SEC1 非压缩 share、
  SHA-256 transcript、HKDF-SHA256 确认密钥和 HMAC-SHA256 双向确认；RFC 会话密钥
  再通过 HKDF-SHA256 扩展为 32 字节内容密钥。双方确认成功后才能保存内容密钥。
- 浏览器把不可导出的内容密钥保存在 IndexedDB；Desktop 不得使用 macOS Keychain 或
  Windows Credential Manager，设备令牌与每客户端内容密钥只保存在应用数据
  目录内经过认证加密的本机 vault 中。Server 只保存设备令牌的 SHA-256 摘要。
- 多浏览器授权不得读取、包装、导出或复用本机 vault 中已有的内容密钥。每个
  浏览器必须通过各自的一次性短码 PAKE 得到独立内容密钥；Desktop 只把该浏览器对应
  的新内容密钥写入独立 vault 条目。取消一个浏览器授权不得影响其他浏览器。
- 设备令牌、邮箱登录令牌、数据库密码、SMTP 密码和 E2EE 密钥都是秘密，不得进入
  Git、命令输出、普通日志或截图。客户端设备令牌与内容密钥只能进入既有安全存储，
  不得写入普通明文配置。Server 秘密放在 root-owned 文件中：仅 root 读取时使用 `0600`，
  服务组必须读取时使用 `0640`。维护者明确授权的本机部署配置副本可保存在被忽略的
  `.secrets/official/`，目录 `0700`、文件 `0600`；不得随源码或构建产物公开。
- Web/Desktop 的 `@noble/curves`、移动端 `elliptic` / `pointycastle` 组合及 Relayune
  的 RFC 9382 profile 尚未完成专业独立密码学审计。维护者已明确本次不委托第三方审计，
  不把该项作为源码公开门槛；继续保持会话在出站前加密、服务端不持有内容密钥的约束。
  不得把 RFC 测试向量、自动扫描或 AI 源码复核称为专业审计或无侧信道证明。
  若未来改变威胁模型或扩大安全承诺，须另行评估实现与验证范围。
  Web 依赖服务端下发脚本，不抵抗服务端篡改前端；
  当前无逐消息 ratchet，不承诺后续客户端内容密钥失陷时的前向保密。详见
  [威胁模型](e2ee-threat-model.md)和[密码学安全复核](crypto-security-review.md)。

## 客户端设备身份与重新授权

- `relay_client_devices` 保存独立于授权的稳定客户端记录：按账户、目标 Desktop 和客户端标识摘要
  派生 `client_device_id`，仅包含所属账户、Desktop、创建时间及单调递增授权代次。
  Android 使用同签名、同系统用户下的 `ANDROID_ID`；iOS 使用 IDFV（卸载同厂商所有 App 后可能变化）；
  Web 在独立 IndexedDB 中保存随机身份，退出账户或轮换密钥不清除它，清除网站数据后变为新身份。
  原始系统标识只在客户端派生摘要，不上传；摘要及稳定设备 ID 不写入日志、反馈或分析事件。
- 标识只用于同账户、同 Desktop 范围内归并设备，不能鉴权。每次重新扫码仍完整执行 PAKE，
  创建独立 `browser_id`、令牌和内容密钥，禁止覆盖旧授权条目的密钥或重用旧密文路由。
- 客户端验证 Desktop 确认值、解密新目录且持久化新凭据后，调用
  `/api/browser/pairings/activate`，使用新授权令牌撤销该设备更早代次的授权。
  激活接口须验证授权未撤销、Desktop 未撤销及配对已确认；并发时旧代次不得撤销新代次。
  网络失败或旧服务端不支持激活时保留新凭据，下一次启动重试归并；此期间可能暂时保留多条授权。
- 没有标识或历史记录未携带标识时，不按名称、机型或 IP 自动合并。被撤销的授权保留，
  稳定设备记录保留，以支持再次扫码时复用设备 ID；设备 ID 不意味着旧密钥仍可用。

## 中转数据严格窗口

中转库是投递缓冲区。实时事件按 envelope AAD 的创建时间保留 10 分钟，查询响应保留
5 分钟；重复上传不得重置期限，外层时间必须与 envelope AAD 一致。传输时间允许至多
2 分钟的未来时钟偏差。过期载荷立即停止读取和重传；Mongo Date TTL 与有查询时限的
分批清理异步回收物理记录，清理旧版本遗留数据及私有响应 blob、崩溃遗留文件。

Desktop 启动及离线运行时同样回收过期 outbox/重试队列/响应副本。有效窗口内仍按独立
客户端确认删除副本，不因全局 ACK 或另一客户端收取而丢弃。过期回收不推进全局 ACK。
写操作去重记录保留至命令的认证过期时间；服务端另留 5 分钟回收宽限，命令有效期最多
24 小时。ACK 后清除命令载荷，但不能随 5 分钟响应一起提前删除仍有效命令的去重凭据。

事件游标已超出窗口时，API 返回明确的 resync_required 和新的窗口游标。Web/手机先
从 Desktop 读取并校验当前会话的加密持久历史，成功后才重置游标；失败保持旧游标重试。
其他会话在进入时重新获取历史。完整历史仍属于本机 Agent 与客户端加密缓存。

## 手机本地历史缓存

手机使用 SQLite 作为本地缓存，不改变服务端 Node + MongoDB 架构。每条消息只保存最新有效
版本，消息和分页检查点在同一事务提交；允许更新及回收可从 Desktop 恢复的缓存正文。
删除标记经过认证且对同一消息 ID 终止，正文淘汰后仍保留最小标记，防止旧页重放恢复删除内容。
缓存缺页不能当作历史结束；实时消息与本地预览不证明历史覆盖连续。

消息正文、工具详情、分页信息和未确认发送内容在写入 SQLite 前使用独立缓存密钥执行
AES-256-GCM 加密，密钥仅存手机现有安全存储。原始会话/消息 ID 使用带密钥摘要建立
索引；本地库允许保留消息时间、删除标记、访问顺序及结构信息，这不是全库元数据加密。
认证数据包含来源序号；优先使用已有事件 AAD 的 `event_seq`，历史读取以请求开始时的已知
来源序号作为合并基线。它不是 Native CLI 的消息版本号；原生历史仍需在重入及回前台时核对。
最近 300 条会话目录、项目列表及增量同步检查点复用该加密存储，以独立记录类型覆盖保存；
缓存按账户、Desktop 与授权密钥隔离。磁盘目录只用于列表预览，不恢复运行状态或覆盖更新目录。
冷启动允许用已保存账户、配对及缓存密钥恢复只读本地内容；完成在线账户和客户端授权验证后才允许
发送命令。身份不匹配、授权撤销或退出时销毁密钥并清理对应正文、标记和待确认输入。
目录首次及恢复时同步，新版手机通过加密请求声明每批最多 300 条（旧客户端默认 50 条），之后只同步变化；展开项目及加载更多只访问本地数据。
在线密文通道与 Desktop 加密 `directory_push_version: 1` 均可用时，由加密目录版本变化
驱动同步，停止每秒远程查询；旧端保留前台每秒定时同步。
同步版本、分页游标及删除/移出目录标记只在原有加密命令响应内传输。详见 [会话目录同步](session-directory-sync.md)。

全部电脑与 Agent 共用最多 **100 个会话正文缓存**，优先保护当前显示的会话，其次保留有
待确认输入的会话，再按最近读取顺序淘汰。后台输出不会刷新已有会话的访问顺序。
正文不设置固定天数，到上限时回收；会话目录、删除标记和待确认输入不占正文名额。
内存保留当前和最近 4 个读取会话；其他运行会话只留最多 100 条消息的尾部。
连续输出最多 2 秒形成一次检查点；写队列按会话及分页游标合并，后台/退出时主动刷新。

已确认消息中的附件只保存引用；下载、上传和旧库中的原图/缩略图统一进入
`image-cache-v1.sqlite`。全手机最多保留 **500 张图片**，同一会话附件的预览和原图合计
为一张，按最近访问顺序淘汰；加密载荷另有 **256 MiB** 上限。命中缓存时不请求网络；
缺失或损坏时回退原有加密下载。图片复用独立本地缓存密钥和单独认证域，索引不保存原始 ID。
未确认输入的附件另外随受保护输入加密保存，不随可淘汰图片或会话缓存丢失。

发送前持久化用户输入及本次准确的密文命令（请求 ID、有效期和设置不变），原生消息回显确认后
清理待确认记录。重启后恢复待确认输入，但不自动重放状态未知或过期的写操作。
旧 SQLite v1 原地事务升级并压缩冗余版本；按有效缓存密钥分批认证和迁移附件、保护旧输入，
迁移完成后执行 100 会话回收。启动维护清理密钥已不存在的命名空间；不能在密钥不可用时把
尚未认证的旧输入当作普通缓存淘汰。详细存储及测试口径见 [手机本地存储](mobile-storage.md)。

历史性能诊断只记录固定阶段、随机请求标识、耗时、计数和字节数。Desktop 计时字段
经响应密文发送，上传完成时刻只在本机记下；不进入服务端明文字段或日志。

macOS 的自动性能日志只留在本机，允许软件版本、时间、本机进程 PID、Relay 启动代次、
固定状态/阶段/操作类别及资源和耗时数值；不得保存会话/设备标识、路径、URL、正文、
凭据或原始错误。子进程指标通过字段、枚举和数值白名单后重新序列化，限速并通过
有界队列写入 0600 文件；采集/写入失败不能阻塞业务。性能文件总量不超过 10 MiB，
记录最长保留 7 天，运行时自动清理；详细口径见 [macOS 性能诊断](macos-performance-diagnostics.md)。

## 修改边界

- 手机电脑网页预览（`local_web_version: 1`）使用独立 `session.web_open` /
  `session.web_request` 密文命令；URL、资源、API 正文、Cookie 及响应头均属于业务密文。
  每个预览只绑定一个显式 loopback HTTP(S) 地址（localhost、127.0.0.1 或 ::1，
  端口 1024–65535）、客户端密钥与会话，30 分钟失效。Desktop 直接连接固定回环 IP，
  不查询 DNS、不跟随重定向、不复用电脑浏览器凭据、不放宽 TLS 验证。
  每次请求和响应均重新核对现有授权新鲜度；其他主机、端口、协议及跨源重定向拒绝。
  所有请求共用现有写命令持久化去重；直连回退保留请求编号和原密文，禁止把超时 POST
  换编号自动重发。无法判定完成状态时提示核对结果。请求上限 256 KiB，响应 12 MiB，
  上游请求最长 20 秒。WebSocket、SSE、跨源 API、外部 CDN 和文件 URL 不在首版能力内。
  手机仅在页面前台存活期间使用随机端口的 127.0.0.1 HTTP 资源渲染器，把解密结果交给
  WebView；它不是会话 broker，不接受 LAN 请求，不在电脑开启监听，不直连电脑网页。
  渲染器要求随机会话 Cookie、精确 Host 和同源 Origin；Cookie 为 HttpOnly/SameSite=Strict。
  网页不获得原生桥接或 Relayune 凭据。CSP 限制资源、脚本、API 和表单到该渲染源，禁用
  worker、子框架、弹窗、设备权限及外部导航。上游 Cookie 仅保存在该预览的内存 Cookie jar，
  不进入 WebView Cookie 存储；JS document.cookie 不用于此站点登录。关闭、切到后台或换号
  立即关闭渲染器并清空 Cookie；Desktop 能力另有超时兜底。

- 手机端可按需预览会话引用的 Codex HTML 图稿：仅接受本机
  `~/.codex/visualizations/YYYY/MM/DD/<task-id>/<name>.html` 生成目录中的常规文件，
  读取时拒绝符号链接，限制 1 MB，仍通过会话附件的端到端加密响应传输。
  HTML 在无同源权限的 `sandbox="allow-scripts"` iframe 中执行；不得注入原生桥接、
  账户或会话凭据。CSP 与 WebView 导航限制禁止外部网络、文件访问、表单提交和弹窗，
  图标资源随 App 离线打包。Codex 宿主 API 和外部依赖不属于本地预览能力。

- 不得添加协议 v1、手工预共享密钥、ECDH 包装密钥、PKCE 桌面回调或 Sites bypass
  token 的兼容分支。
- 新增 Server 字段前先判断能否由现有密文 envelope、路由元数据或本地状态表达。
- 已授权客户端的 `client_version` 是可选的公开软件版本元数据，供 Desktop 展示。
  首次授权时记录，后续仅在客户端通过既有授权鉴权后更新；缺失或无效上报不清除旧值。
  它不包含会话内容，不作为授权或安全校验依据。
- 账户侧栏排序为跨浏览器同步的界面偏好，保存在 MongoDB `auth_users.preferences.agent_order`；侧栏可见 Agent 存入同级 `visible_agents`，同样只包含公开 provider ID。
  只允许公开的 Agent provider 标识数组；读写通过邮箱会话绑定当前账户，写入须同源。
  不保存设备、项目、会话标识或内容，不依赖 Relay 在线状态。
- Server HTTP 日志采用 schema_version=2：记录服务名/部署版本、固定事件类型、级别、
  方法、路由模板、状态码、毫秒耗时、白名单错误码、独立随机 trace_id、认证类型、
  可可靠判断的客户端类型，以及认证成功账户的 user_ref。user_ref 使用日志专用密钥对
  规范化邮箱做带域分隔的 HMAC-SHA256，并附密钥版本前缀；不得直接记录邮箱、原始用户 ID
  或不带密钥的邮箱摘要。匿名/认证失败且无已确认账户时省略 user_ref；缺失日志密钥时
  同样省略，禁止生成临时密钥或复用任何业务密钥。密钥文件使用 root 0600 或服务组可读的 0640。
- trace_id 由服务器独立生成，不接受入站 trace/user 标识，也不复用业务请求编号。
  客户端类型无可靠依据时为 unknown，不根据 User-Agent 或客户端自报值推定。
  禁止记录请求体、响应体、原始异常堆栈、完整 URL、IP、User-Agent、Authorization、Cookie、
  邮箱登录 token、业务会话 ID、配对 share 或确认值。稳定 user_ref 仍是可关联账户的信息，
  应限制日志查询权限和保留期。字段定义见 [HTTP 日志 v2](request-log-v2.md)。
- MongoDB 索引、查询和更新必须可在单实例自托管 MongoDB 上工作；配对、桌面登录与邮箱登录过期
  数据使用 TTL 索引。


## 网络用量统计

允许单独输出 `event=network_usage`、该事件自己的 `schema_version=1` 分钟聚合日志，
不改变 HTTP 请求日志 v2。仅保留服务版本、时间窗口、固定 HTTP 方法/路由模板、
传输类型、白名单 WebSocket 消息类型、收发载荷字节数、请求或消息数量、提前断开数。
不得加入用户、设备、会话、请求标识、原始路径/查询、报文、凭据或动态消息类型。
进入独立 SLS Logstore，采集器必须严格校验完整白名单外壳，丢弃源字段和未知字段。
统计口径与上线顺序见 流量调查（内部验收档案未随公开源码提供）。

## 用户主动反馈

- 用户明确要求反馈直接可读：反馈描述、类型、用户主动添加的最多三张图片、选填邮箱和微信号，以及 App 版本、机型和系统版本以普通字段
  保存到 MongoDB `relay_feedback`，供维护者直接查看和处理；无需反馈密钥或解密工具。
- 客户端只附带界面上明确展示的环境信息，不自动附带会话、日志或设备唯一标识符。
  用户明确选择「附带退出诊断」并预览后，可随反馈描述提交受限生命周期摘要：时间、公开版本、
  固定阶段/错误类别、退出码、信号、运行时长及报告内临时运行编号。最多 3800 bytes，读取最近
  7 天可用记录；不得附带原始日志、堆栈、路径、进程 PID、设备/会话标识或任何凭据。
  反馈与会话数据分开处理，此例外不适用于 PAKE、凭据、聊天内容或其他会话载荷。
- 提交仍使用 HTTPS 和现有邮箱会话或有效 Desktop 设备凭据鉴权，不要求在线 Relay。
  服务端严格校验字段、限制大小、原子限流并支持幂等重试；不把反馈正文或请求体写入日志。
- 维护者通过已有受限数据库访问查看记录，不公开反馈读取接口。字段和查询示例见
  [用户反馈](feedback.md)。

## 管理员监控账户关联

只有部署者通过服务端 `MONITOR_ADMIN_EMAIL` 显式配置的管理员，其已验证邮箱会话才可查看
最近活跃账户邮箱及按邮箱检索 HTTP 诊断记录。未配置时拒绝所有账户，不存在默认管理员；
静态页面输入的邮箱仅用于登录，不能授予权限。邮箱从现有账户数据读取，以日志专用 HMAC 关联 user_ref，仅在管理员响应中展示；
不得上传 SLS 或写入日志。关联结果只短时缓存在内存，不新增持久化反查表。

用户名模式改用独立的 `MONITOR_ADMIN_USERNAME` 显式授权，不自动给实例所有者监控权限。
未配置日志供应商时，自托管监控仅返回真实数据库与进程状态，明确 `logs_available: false`；
不查询官方服务、不伪造日志统计或邮箱关联。前述邮箱关联能力仅用于邮箱账户。
邮箱搜索使用同源 POST body，不放入 URL；仍不得返回业务请求体、响应体、密钥或会话明文。

管理员监控可展示已认证账户客户端自报的软件版本与平台（macOS、Windows、iOS、Android、Web）。
仅在成功响应后记录白名单平台、严格校验的版本号和服务器接收时间，保存在现有
`auth_users.client_versions` 每平台一个最近观察值；不记录设备标识、系统版本或会话内容。
客户端自报平台不改变日志 `client_type`，不作为身份或授权依据；缺失或无效值不覆盖旧值。
