“不依赖官方服务”指 Relayune 自身的账户、设备、配对、会话、附件、反馈与配置等流程。
Agent 使用的模型和供应商仍按用户自己的账户与接入运行；开源不提供第三方模型凭据。
静态帮助或项目来源链接可以保留，但访问、更新检查、社区拉取、推送和统计不得成为核心运行前提，
也不能在自托管模式下静默向官方发送实例或用户数据。官方注册策略不自动用于自托管实例。

官方服务沿用本仓库主干，不合回旧私有库继续双线维护。联合升级步骤与边界见
[官方服务与客户端升级准备](official-deployment.md)；官方配置使用 [.env.official.example](../.env.official.example)。

### 2. 无 SMTP 的实例初始化与登录

`server/email-auth.ts` 现在按显式模式处理官方邮箱账户和本地用户名账户；不能把两种模式指向同一旧数据库。
本地账户使用不可变账户 ID，不伪造已验证邮箱；唯一实例所有者通过本机命令初始化和恢复。

- [x] 提供明确的官方邮箱模式与自托管用户名模式，前端根据服务能力展示对应登录流程。
- [x] 初始化阶段只允许部署者取得本实例初始化权；不能将“首个公网访问者”直接认作管理员。
- [x] 默认用户名可为 `admin`，密码由部署者首次设置；不提供 `admin/123456` 等通用初始凭据。
- [x] 并发初始化只能成功一次；重启、重复安装或升级不覆盖管理员密码。
- [x] 密码仅保存强密码摘要，保留登录限流、会话过期、撤销与日志脱敏。
- [x] 账户身份与邮箱属性分离；设备归属、PAKE、客户端密钥与反馈等依赖邮箱的路径一并适配。
- [x] 提供不依赖邮件的本机管理员恢复方式；恢复不能绕过远程权限检查或泄露原密码。
- [x] 不把自托管管理员自动映射为官方服务管理员；监控权限仍由本实例显式授予。

### 3. 异地访问与安全连接

部署者可自备 VPN 或公网入口；不提供依赖 Relayune 官方中转的自托管方案。
“不用手动准备证书”是安装体验目标，不是允许把远程账户登录改成未保护的 HTTP。

- [x] 确定 VPN 与公网入口两种支持路径及服务地址、端口、证书信任的首次引导。
- [ ] 分别验证 IP 地址和无独立域名场景；自动证书或实例证书方案需验证持有证明、信任与更新。
- [ ] 浏览器、macOS、Android、iOS 分别验证连接安全策略，不提供全局忽略证书校验开关。
- [x] 若采用实例私有证书，明确受信引导与密钥变化提示，不能把首次接触自动等同于可信。
- [ ] 浏览器安全上下文和密码学 API、Cookie、跨域策略按实际访问方式验证。
- [x] MongoDB 和私有 blob 保持隔离，不因开放访问而公开数据库或静态暴露附件。

已实现外部目录生成 CA、IP/DNS SAN 证书与 Nginx 配置，Mobile 按实例导入公开 CA，Desktop/Web 使用系统信任。
隔离 TLS/WSS 测试已覆盖受信、错误 CA、主机名和重定向；iOS 模拟器私有 CA 流程已验证，
macOS 系统信任安装及真实手机仍待验证。现有 HTTPS、MongoDB 和秘密文件约束继续生效，
不为“低配置”直接添加跳过验证或固定共享密钥的分支。

保留反馈、社区和监控入口；未配置的外部功能明确显示不可用。

- [x] 服务能力发现不以相同用户名或邮箱视作相同账户，不把凭据发送给未经确认的新地址。
- [x] 社区、反馈、监控、法律说明、更新检查与推送按实例配置，不将用户数据回送官方。
- [x] 反馈和运营模块保留；未配置时显示本地说明或不可用状态，不展示失效群码、假数据和假成功。

- [x] 在隔离测试中阻断 Relayune 官方域名，验证登录、配对、任务和反馈仍可完成。
- [x] 更新渠道与服务实例分开：官方签名应用只接受受信官方更新；独立发行使用自己的签名和渠道。
