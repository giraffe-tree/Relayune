# 手机后台生命周期与耗电策略

## 时间与工作类型

任务执行留在电脑。手机后台不维持实时输出订阅，不为了五分钟缓存期限申请后台保活。

| 阶段 | 行为 |
| --- | --- |
| 短暂失焦（inactive） | 停止 Flutter ticker 和文字展示节奏；保持连接，避免权限弹窗、通知面板引发完整重连 |
| 真正进入后台（hidden / paused / detached） | 关闭在线流、旧实时连接和 WebRTC；取消续租、目录同步、健康检查、重连与事件重试；刷新待写历史检查点一次 |
| 后台不足 5 分钟 | 保留当前会话视图、草稿和内存缓存；不新增实时同步或推送登记轮询 |
| 后台达到 5 分钟 | 释放可恢复的正文、会话视图、Markdown 组件和图片内存；保留目录、同步游标、草稿、待确认输入和磁盘缓存 |
| 后台遇到内存压力 | 提前执行同样的内存释放 |
| 回到前台 | 先从磁盘恢复当前会话，再恢复连接和核对原生历史；当前打开的电脑优先，其他电脑依次恢复 |

截止时间只安排一次普通 Dart timer，不使用周期任务、精确闹钟或保活服务。系统挂起期间 timer
可能不运行，因此记录离开时间，回前台时再次判断五分钟期限。视图代次保证即使释放与恢复发生在
同一帧，旧 Markdown/图片组件也会重建。短暂失焦不重置离开时间，不把后台回来的 inactive 当作前台。

- **展示工作**：后台立即停止动画与文字展示；图片等待读取取消，已开始的只读响应不再触发后续分块和轮询。
- **用户操作**：已发起的单次发送及落盘可以有限收尾，沿用请求超时与系统执行限制。待确认输入和
  原始密文请求继续受保护，不因连接关闭或恢复而盲目重发。
- **通知工作**：APNs、极光/厂商推送保持已登记的投递能力。应用进入后台不会注销通知或停止 SDK 推送。
  主应用不为了接收通知持续同步完整会话。
- **维护工作**：缓存维护不在后台启动，旧历史迁移在批次边界暂停；安卓自动更新停止 APK 响应流并
  清除未校验的 `.part`，之后沿用更新检查节流，不把半成品当作可安装包。

## 数据保护

内存正文只有在当前不可变消息对象已成功写入、或来自已认证磁盘读取时才释放。失败或未完成的
检查点、读取中的会话、未确认用户消息保持在内存，避免错误地把未保存内容当作可恢复缓存。
回到前台使用 local-only 读取先显示磁盘正文，随后核对 Desktop；缓存覆盖缺口与历史游标规则不变。

输入草稿、待选附件和阅读位置由会话级存储对象保留，释放视图不清除这些对象；这里不新增未发送
草稿跨进程的持久化承诺。已经提交的待确认输入仍按现有 SQLite 加密保护规则保存。

五分钟只影响内存，不影响磁盘的 100 会话 / 500 图片 LRU，也不影响账户、配对或服务器推送记录期限。

## 推送登记

Android 删除每分钟检查循环。账号、推送地址变化及回前台触发检查；正常前台登记最多六小时续期
一次，采用单次预约。失败只在前台按 1、2、4 分钟重试三次，后台取消预约，新外部事件可重新尝试。
通知关闭后同一身份只成功注销一次；再次启用并登记后，后续关闭允许新的注销。

iOS 同样延后后台的主应用登记和 native snapshot 查询，回前台处理变化；后台推送扩展和系统投递
不受影响。已开始的一个登记请求可结束，但不会启动下一个电脑的登记。

服务器目前 Android 登记期限七天、iOS 三十天，仍按既有协议续期。本轮不修改服务器、Relay、
通知载荷或生产配置；连续后台超过登记期限后的投递问题需要单独调整服务器清理政策。

## 验证范围

自动化覆盖重复后台事件、短暂失焦、五分钟截止、系统挂起不执行 timer、内存压力、旧请求晚返回、
后台重试停止、推送续期/注销去重、有限失败重试、加密缓存释放及本地恢复、草稿视图重建、
自动更新下载中断与清理，并回归会话、附件、目录、在线流和受保护发送。

模拟器可验证切后台、长时间离开和恢复，但不能提供真机电池耗电百分比，也不能替代安卓厂商
推送或 Android Doze 的真机验收。本轮不重启 macOS 端，不推送远端，不发版或部署。
