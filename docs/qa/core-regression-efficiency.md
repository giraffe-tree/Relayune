# 核心回归提速与可恢复执行流程

维护日期：2026-10-06。每次执行[核心回归口令](core-regression-prompt.md)必须读取并应用本文。
依据：2026-09-10 r1（内部验收档案未随公开源码提供）暴露的超长等待、重复 UI 定位、零散安装和共享版本变化。
补充经验：2026-09-11 r1 的共享安装覆盖、重复 Relay、页面延迟、键盘布局及子任务恢复测试；该轮仍有未闭环项，以下经验不代表整轮通过。
本文是立即生效的执行约定；现有真实 CLI 脚本可复用，一键编排器、自动诊断采集和稳定 UI 标识仍属待开发能力。

手机启动、历史打开、新建/回复和后台实时同步专项复测，另读[快速复测方法](mobile-performance-quick-run.md)。它将 2026-10-05/06 的三轮实测、时钟边界与受控竞争用例固化；数字日志过滤和汇总复用现有脚本，不另建测试编排层。

## 1. 先确定范围，一次预检

- “跑核心 case / 核心用例 / 核心回归”仍覆盖当前全部 P0/P1；不得为了提速默认缩成冒烟测试。
- “继续”读取最近报告及检查点，先处理 failed、blocked、not-run。此前通过项只有在相关代码、CLI、配置、平台与前置未改变时才可引用，并保留原 run_id 和版本；失效项重新执行。
- 新一轮完整回归可以复用准备方式和有效登录，但不能用旧报告通过数冒充本轮执行数。冻结每个叶子的实际平台、Agent、示例参数，不能用含糊的“三端通用”合并结果。
- 在大量 UI 操作前，一次检查：源码与安装指纹、Desktop 存活、各客户端独立授权/在线状态、实际适配器解析的 CLI 路径/版本/登录/能力、所需真机、模拟器占用、其他任务的安装与重启活动。
- 对待测 Agent 尽早执行一个专用会话的短回复探针，确认真实执行及终态；该动作满足对应首轮用例时共享证据，不再额外跑同样的冒烟。预检失败只阻塞依赖分支。
- 一次集中说明实际缺少的用户输入、硬件或权限，继续独立工作；不重复询问已授权事项。有效配对直接复用；需要新配对时在准备好输入之后才打开短码，避免等待期间过期。首次登录单独准备隔离实例，不退出共享账户。

## 2. 保持一个可核验的验收版本

取得模拟器占用不代表独占 Desktop。每条真实链路开始前和安装前检查共享 Desktop 是否有其他任务使用，遵循现有设备协调流程；不要声称已经有额外的 Desktop 全机锁。
存在冲突时保留检查点，先做协议测试、夹具准备或文档等独立工作。等待期间不停止他人任务、不覆盖应用；对外消息与授权仍按当前工具规则执行。

预检使用一个证据窗口 ID，集中记录源码提交、Desktop 与嵌入 Relay 的签名/文件指纹、Web 构建来源、iOS 构建来源，以及 Relay PID、PPID、启动时间与在线状态。版本字符串相同不代表产物相同；进程存活也不代表连接正常。组内没有变化迹象时引用该窗口，不在每次点击前重读完整环境。

安装、重启、跨端恢复或异常延迟后重新核验。发现多个 Relay 时先核对路径、父子关系、启动时间和归属；不能仅凭 PPID 为 1 就认定可停止，也不能凭检查点中的旧 PID 操作。记录重复进程这一事实，把它与“是否导致事件延迟”的因果推断分开。没有已授权且可安全执行的恢复方式时，继续独立工作。

桌面占用只覆盖实际鼠标键盘操作；构建、模型执行和日志分析期间释放桌面席位，设备 ticket/lease 按 skill 保留。锁屏或外部焦点变化时保存具体待操作页面和未发送草稿，避免恢复后重复发送。

版本变化后保存原证据，记录新指纹和变更范围；只让受影响的断言失效，不从头重跑所有项目。隔离 worktree 避开用户改动，保留依赖和构建缓存。

## 3. 一组夹具跑连续旅程，每步立即落盘

按[链路顺序](core-test-execution-order.md)复用 S/T 会话；先准备不同的随机标记、图片、批准/拒绝输出路径及长历史。不要用几十次真实模型请求生成仅用于分页的编号历史；合成历史必须明确标注，另用真实新回复验证实时追加。
审批、停止、重连等有状态用例在运行前核对前置；同一文件路径已经被用过时生成新路径，不能让旧副作用决定新用例结果。不同 Agent 的能力及结果分别记录。

每个关键步骤完成或失败后，立即更新本轮目录中的 results.json、operations.json 和 checkpoint.json；不要等最终总结才手工拼记录。现有脚本不产出这些文件时由执行 Agent 写入，不假定自动生成。

checkpoint.json 至少保存以下内容（不保存凭据）：

| 字段 | 内容 |
| --- | --- |
| run_id、updated_at | 当前轮次及最近落盘时间 |
| builds | 源码、安装指纹、平台、实际 CLI 版本；新版本另加记录 |
| fixtures | 本轮专用项目路径、会话 ID、夹具用途与所有权；独立平台/Agent 明确归属 |
| completed_operations | 已保存的操作证据 ID；关联 results.json，避免重复计时 |
| next_steps | 下一用例及具体前置，例如“T 已停止且空闲，下一步追问标记” |
| evidence_window、active_operation | 当前证据窗口、在途操作及绝对截止时间；没有在途操作时明确为空 |
| resume_state | 当前页面、未发送草稿、最后已确认动作、下一断言及证据文件路径 |
| pending_issues | 问题 ID、失败阶段、依赖项、已尝试次数及解除条件 |
| owned_resources | 自己的设备 lease/ticket、测试进程及清理状态；不得凭旧 PID 直接终止进程 |

恢复前重新核验版本、授权和会话状态，不能直接相信检查点中“在线/运行中”。检查点必须覆盖跨对话摘要后的接续；持久文件中的路径和 ID 比重新猜测可靠。

## 4. 分阶段观察，截止时间不随轮询重置

所有操作开始前记录 started_at 和绝对 deadline。以下是执行预算，不是产品性能 SLA；用例已有更明确时间要求时以用例为准，并记录采用值。

| 阶段 | 默认处理 |
| --- | --- |
| 普通页面切换、弹层、输入响应 | 30 秒仍未完成：保存现场并区分 UI 工具定位失败与产品无响应 |
| 命令已发送但接受/执行阶段不明确 | 30 秒进行一次只读诊断：命令状态、真实 Agent 事件/测试历史、Relay PID/指纹；不单凭没有首字就判失败 |
| 普通真实 Agent 轮次 | 从发送起总计最多 180 秒；中途刷新、切页或读日志不得重置截止时间 |
| 事先声明的受控长任务 | 默认总计最多 240 秒；需要其他预算须在执行前依据用例记录，不能失败后无限续时 |
| 等待用户审批、登录或硬件 | 分开记录 user_wait，不计成模型执行延迟；继续独立分支，不将超时视为用户同意 |

真实执行出现错误、进程退出或连接失效时可提前结束等待。达到截止时间，保存当前阶段和脱敏证据，按用例结果记失败、将有明确依赖的后续动作记 blocked，然后继续独立分支及缺陷定位。
只对有证据的暂时性故障重试一次，保留首次结果；修复或环境发生实质变化后的复测另记 attempt 和版本。没有新证据不重复重启、重复发同一任务或等待数分钟。
操作失败不能成为停止整个已授权任务的时间预算；仍需推进剩余可执行项和修复。

诊断只读本轮测试数据，按 session/turn/request 关联接受、启动、首字、完成，避免旧轮次事件冒充本轮进展。内容密钥、短码、token、Cookie 不进入报告；不得为观测让 Server 接收会话明文。

## 5. 减少 UI 工具试错和重复模型调用

- 操作前读取当前可访问性状态，优先通过当前界面的语义标签定位。元素失效时刷新状态再定位，不沿用旧编号。
- 同一操作连续两次没有预期变化，保存现场并改变定位方式或诊断工具问题，不继续盲点、盲拖。坐标必须来自当下可见界面，不能跨窗口尺寸复用。
- iOS 模拟器先聚焦输入框并确认状态，再输入，发送前核对完整文字；本轮工具曾吞掉首段。替换单段草稿可三击文本框、确认选择菜单后再输入；`selectText` 或 `super+a` 未实际选中时不要继续删除字符。
- 重装 macOS 后重新确认文件夹权限，不能沿用重装前的成功提示。用户已授权代点时直接处理；若工具拒绝系统弹窗进程，保留弹窗、记录 user_wait 并明确请用户完成，不改系统权限数据库绕过限制。
- 固定复用已验证的导航、输入和滚动方法；模拟器文本区域拖动可能变成选中文字。每次滚动验证首尾标记与位置变化，再进行下一步。
- 等待真实模型时可做不争用 UI/设备的独立读取和确定性测试；共享桌面交互保持串行，不擅自引入多 Agent 同时点击。
- 一次真实回复可共享列表/代码等多个断言，但每个断言独立核对。先保留旧阅读锚点，再触发或等待新回复，不能回复已经完成后才开始验证“新消息不打断阅读”。
- 用户答案来源不明、其他客户端操作或共享版本变化时记录证据受干扰，先定位来源，不将结果判为通过或直接归因产品缺陷。

### 2026-09-10 r3 可复用操作

- Chrome 原生 AX 可以用于标签页内测试；扩展 Tab 接口本轮多次超时。若原生接口只返回空菜单且截图不可用，刷新状态、取消菜单与直接定位已确认标签均失败后记录工具阻塞，不重启用户浏览器或反复重试。
- Web 文本输入优先 `setValue` 后核对全文；模拟器输入先单独点击文本框，再输入 ASCII 标记，发送前核对。模拟器 `typeText` 可能收起软件键盘，键盘布局用例需再次按 `super+k` 并截图确认键盘确实显示。
- 文件选择器里，测试文件的 AX 图像若暴露“打开”次级动作，可直接执行该动作；本轮“前往文件夹”输入与单击文件未能可靠完成选择。不要把工具定位失败记成附件功能失败。
- 子任务列表的 AX 文本点击可能不触发导航；先截图，点击该行可见箭头。子任务审批默认两分钟有效，优先处理审批，再探索详情，避免导航耗时让请求过期。
- 配对回归要同时记录 Relay PID，并让另一专用会话等待可回答的问题；新增客户端后回答原问题，才能证明配对未重启或打断既有任务。
- 权限恢复回归记录真实 `turn_context` 中 sandbox/approval_policy，重启前后各执行一个无工具短回复；不要仅凭 UI 选项认为沙箱保持不变。

### 精简证据读取与 token 开销

- 每个操作预先确定要观察的断言。优先读取工具支持的局部 AX 状态或差异；首次定位、窗口变化或元素失效时才取完整树。完整树刷新后重新定位，不能继续使用旧元素编号。
- 布局溢出、键盘遮挡、图片、滚动锚点等视觉断言必须检查截图；普通按钮状态或文本断言可用 AX。不能为省 token 省略必要的视觉证据，也不需要每次同时获取完整树和截图。
- 日志先按本轮 session/turn/request、时间窗口和事件类型筛选，只返回诊断所需片段与统计；完整脱敏证据保存文件并引用路径。不要反复读取整份历史、整份结果或无关会话。
- 已确认命令接受后，按下一阶段的预期完成时间安排观察；普通长任务不每秒查询相同页面。需要首字/审批延迟时使用事先约定的采样间隔，注明观察精度；截止时间保持不变。
- 接续先读 checkpoint 和结果摘要，再定向读取未闭环项的操作及日志。仅在记录冲突或证据缺失时扩大读取范围；不从聊天历史重新猜会话 ID。
- 原生已完成但页面仍等待时，保留原轮次，检查 Relay 传递、客户端接收及渲染阶段；不要用重复发送短回复或重跑 CLI 掩盖页面未完成。

## 6. 按批次修复与安装

能继续正常测试的问题先保存最小复现和依赖关系，完成当前独立链路后集中修复；阻断大量后续用例的问题立即优先修复。这个安排不免除本轮修复责任，也不要求等所有问题解决后才进行必要验证。

修复采用“失败回归 → 修改 → 相关检查 → Git 提交 → 从该批最终提交构建安装 → 真实链路复测”。一批只安装一次；后续有相关修改或构建失败才再构建。按根 AGENTS.md 完成最终本地安装，不重复安装同一已验证指纹；纯文档不构建。
修复前记录影响矩阵：问题根因、涉及平台/Agent/配置、必须复测的失败用例与相邻链路、仍可引用的通过项。合入最新主分支后对实际交叉修改补充相关检查；合并或构建成功不自动关闭页面缺陷。

请求捕获测试按语义分类，区分后台读取和用户决定；新增子任务发现等后台请求后，不应继续假设“第一条请求就是审批”。仍须校验目标会话、决定次数、审批载荷及副作用，不能通过删除关键断言让测试变绿。

相关测试通过后不无理由重复全套测试。共享协议、安全、跨端状态等变化按影响扩大覆盖；协议或 widget 通过不能代替真实 UI、真实 CLI 和真机通知。

## 7. 报告能解释时间花在哪里

关键操作按证据 ID 记录；计时不足时填 null 和原因，观察上界不能写成纯产品/模型耗时。额外保存本轮阶段区间及分类：test_execution、diagnosis_fix、build_install、tool_overhead、user_wait、resource_wait。
可从工具记录可靠获取时，额外记录场景的工具调用次数、完整 AX 读取次数、截图次数、重试次数和重复模型请求次数，用于定位高开销步骤；实际 token 用量仅在平台提供时记录，否则填 null，不用调用次数冒充 token。统计可在阶段结束时汇总，不要求为每次点击额外调用工具。
并行区间可以重叠，汇总时分别给墙钟时间和各分类时间，不能直接相加。没有可靠边界不事后猜分摊，也不承诺未经测量的提速比例。

结束时核验用例唯一键、P0/P1 分项计数、证据引用、构建来源和仍待执行项；保存清理记录、释放自己的占用，更新测试树入口并提交报告。不因其他任务排队就把剩余用例写成通过；需要让出设备时保留可恢复检查点及未完成范围。
