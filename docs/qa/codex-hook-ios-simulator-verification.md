# Codex Hook 的 iOS 模拟器复验方法

真实设备、任务 ID、临时日志与历史验收结果留在私有维护仓库，内部验收档案未随公开源码提供。本文只规定复验边界，不代表本副本已完成真实页面或 Codex Desktop 自动触发验收。

## 分层验证

分别验证 Hook 客户端调用、Desktop 本机 Hook socket、已授权手机的 E2EE 审批通道、手机选择回传，以及原生请求的终态与实际文件副作用。测试脚本显式调用 `runCodexHook` 只能证明该测试桥接路径，不能替代 Codex 自动触发已注册 Hook，也不能替代官方 Desktop 原任务的 owner 链路。

使用独立临时项目与合成任务；命令副作用只能位于本轮项目目录。测试白名单必须精确匹配命令及确定等价的 shell 引号包装，不使用包含某个命令词就放行的规则。不得复制账户令牌、内容密钥或 vault。

## 核对结果

- 允许一次：手机展示正确命令，源请求收到允许并进入终态，文件副作用与预期内容完全一致。
- 拒绝：手机和源请求均进入拒绝终态，文件不存在；显示文案不能代替文件检查。
- 交回 Codex / 超时：空决定不转换成允许；分别验证按钮触发与超时回退，排除竞争。
- 自动触发：核对确切 Hook 的注册与原生信任状态，再从原生入口产生新任务；显式脚本调用不能作为自动触发证据。
- 页面：检查滚动、紧凑布局、中文文案、终态与等待提示是否一致，不能只以可访问性树中存在按钮认定触摸可达。

不修改原生信任数据库，不增加信任绕过，不把测试桥接器部署成生产审批接管。模拟器安装与操作需采用可用的设备管理流程；维护者使用的私有 skill 和设备登记不属于公共仓库提供的能力。

每轮分别记录协议检查、真实 CLI、官方 Desktop 和手机页面的通过、失败与未覆盖范围。模拟器截图、个人设备标识和完整日志留在仓库外，公开报告只包含脱敏后的结果与限制。
