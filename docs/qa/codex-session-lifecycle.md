# Codex 会话卸载与提交去重

范围：仅修改本机 Relay 的 Codex 适配器及本地 outbox 标识回执。不修改服务端架构、E2EE、手机 UI 或现有运行实例；不借用归档、删除、终止共享进程来解锁会话。

## 提交与恢复

- `clientUserMessageId` 是关联标识。本机原生协议实验中，重复 `thread/queue/add` 使用同一 ID 会产生多个队列项并执行多次；不能依赖 Codex 提供幂等执行。
- Relay 的命令重试继续按原 `request_id` 和密文处理。Codex 普通消息另外按 `(sessionId, clientMessageId)` 保留本地提交记录，在实际分发前持久化。
- 回执只允许标识、时间、接受模式及 native turn/queue ID，不保存正文、附件、权限或错误文本。当前最多保留 1000 项；新提交回收超过 24 小时的记录，容量不足时拒绝新增，不盲目丢弃未过期记录。
- 已接受的消息复用原结果；状态未知的提交查询原生队列及历史，以消息 ID 精确匹配，不按正文去重，不盲目重发。不同消息 ID 即使正文一致，也允许各自执行。
- 已入队消息在显式发送/重试中发现无人加载时，只执行 `thread/resume`。恢复会话会自动消费原队列，不再为同一消息调用 `turn/start` 或第二次 `queue/add`。
- 写锁竞争以 native RPC 结果为准。Desktop 取得 writer 后，普通消息复用现有 IPC/queue 路径；立即追加、替换消息、带运行设置的发送与原生继续动作保留各自语义，不能把设置静默丢入不支持设置的队列。
- 原生用户消息事件、权威历史或队列执行确认可以补齐丢失的提交回执。后台跟踪保持只读，不因为超时获取 writer。

这是当前 Relay 的有限本地防重机制，不是所有第三方客户端之间或跨任意崩溃窗口的事务性 exactly-once 保证。手动创建新的消息 ID 表示一次新的发送。

## 空闲生命周期

1. B 保留“已加载”与“执行中”的原有区分，并增加“已退订、等待 native 卸载”。
2. 空闲检查与发送沿用同一会话控制队列。默认空闲 5 秒后验证，暂时阻塞时每 30 秒重查；新控制或新活动使旧的退订检查失效。子任务开始活动会同时使父链检查失效；结束后无需再次发送即可重查父会话。
3. 历史必须已落盘且归属正确。正在运行、待审批、待回答问题、可继续的中断任务、持久化未确认、待消费队列、活跃子任务或后台终端均阻止退订；状态缺失、读取失败或接口不支持时保留订阅。
4. `thread/unsubscribe` 成功仍视为 B 持锁。等待期的新发送先恢复订阅；若 A 已抢先持锁，则撤销陈旧本地所有权并走原投递路径。
5. 收到 `thread/status/changed:notLoaded` 或 `thread/closed` 后，串行查询 B 的 `thread/loaded/list`。只有确认未加载才清理所有权、活动和权限缓存；迟到事件不能清掉刚恢复的运行实例。

官方文档描述最后一个订阅者离开且无活动 30 分钟后卸载。本机无真实账号隔离实验中，`0.160.1` 约 60 秒，`0.164.0-alpha.11.1` 两轮分别为 1802、1800 秒后发出原生 `notLoaded` 与 `thread/closed`，B 进程均仍存活。版本/环境的实际宽限期不能写死，产品以原生通知及加载列表确认为准。参见 [官方 app-server 文档](https://learn.chatgpt.com/docs/app-server#unsubscribe-from-a-loaded-thread)。

## 验证

单元与适配器回归覆盖并发重复、相同正文不同 ID、提交前/后磁盘失败、回执超时、持久化重启、已有队列自动消费、writer 竞争、迟到关闭事件、退订与发送竞态，以及审批/问题/子任务/后台终端阻止释放。

本次最终回归为 486 项通过，覆盖 `codex-*`、outbox、多适配器及 HTTP/WebRTC/E2EE 相关测试；类型检查通过，修改文件的 ESLint 无错误（3 项既有未使用变量警告）。没有执行安装、发布脚本或全量生产验收。

可选原生集成实验：

```sh
node scripts/test-codex-session-lifecycle.mjs --codex-bin /absolute/path/to/codex --wait-idle
```

脚本在独立子进程配置临时 `CODEX_HOME` 和本机确定性模型 fixture，不读取真实模型凭据；不启动 Desktop/Mobile，不触碰现有会话。不传 `--wait-idle` 时只验证短链路，通过结束探针自己的 B 建立无人加载状态，不冒充验证原生宽限期。

脚本使用实际 `CodexAppServerAdapter`，验证并发防重、丢失回执后重启不重放、等待卸载期间恢复、原生退订卸载、A 接管后的跨进程队列，以及 B 恢复已有队列而不重复提交。输出临时目录与结构化结果。

`0.160.1` 与 `0.164.0-alpha.11.1` 均通过完整原生链路，每轮恰有 6 次本机 fixture 请求、0 次外部模型请求；卸载后核对了 B 的加载列表且随后由 A 成功获取 writer。等待期间没有修改 native 卸载期限、归档会话或结束 B 进程。

原生实验的模型响应由本地 fixture 提供；它不替代真实模型、真实手机/桌面 UI、复杂 MCP 工具与后台任务的完整用户验收。现用应用的安装、重启和发布不属于本次源码改动范围。
