# 手机打开历史消息：关键路径优化

2026-10-02 已补齐原生模拟器及现有授权的实际度量，并减少重复读取、解密和启动正文预读。

缓存/网络并行化的设计和当时验证口径；“尚无实测”仅描述当时状态。

## 目标与拆解

用户等待的是首屏有可读消息，以及最新历史补齐；页面路由打开本身不等于历史加载完成。

- 内存命中：现有消息立即渲染，后台刷新。
- 磁盘命中：读取加密分页与最新消息版本，解密、合并后显示。
- 无缓存：发送加密命令 → Desktop 读取历史 → 加密响应传输 → 手机解密、删除校验、合并与首帧。

令 C 为缓存恢复，N 为网络及 Desktop 请求响应，M 为合并与显示。原先最新历史需要 C + N + M；本次将独立的缓存恢复与网络请求重叠，关键路径约为 max(C, N) + M。CPU 竞争、调度及删除校验仍有成本，此公式不是实机测速结果。

## 本次修改

打开最新历史时立即启动既有加密请求，并行恢复缓存。缓存仍先发布，远端结果随后按原有规则校验与合并。异步网络失败立即捕获，等缓存路径结束后统一进入原有错误处理，避免未处理的 Future 异常。

缺少分页检查点但存在实时预览时，原来会重复查询并解密最近 20 条消息；现在只读取一次。上翻旧历史仍优先缓存，命中不发请求。页大小、协议、加密、缓存隔离、删除标记与连续覆盖语义保持原有约束。

## 验证与限制

新增确定性测试阻塞缓存读取，确认历史请求与响应读取已经发生；解除阻塞后验证历史合并，并检查最近预览仅读取一次。现有缓存测试改为等待实际缓存显示，且网络响应仍被阻塞，不再依赖旧的串行请求顺序。

通过 controller history、SQLite history store、history recovery 与 conversation resilience 共 94 项测试，以及修改文件静态分析。覆盖分页缺口、删除后不复活、解除授权、实时消息合并和错误重试。

尚无真实手机在同一会话、同一网络下的前后 P50/P95 数据，不声称固定毫秒数或百分比提升。现有 cache_read_ms、command_posted_ms、response_received_ms、merged_ms 与 display_ms 可用于后续对照；本次 response_received_ms 在响应实际完成时记录，避免把后续缓存等待计入网络阶段。

后续测量应分开冷启动、磁盘命中、内存命中，并对短会话、长会话及含附件会话分别统计。优先依据阶段耗时决定是否继续优化 Desktop 历史读取、传输或首屏布局。
