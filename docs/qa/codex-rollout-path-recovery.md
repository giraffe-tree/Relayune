# Codex 会话文件路径失效恢复

## 问题与实现

历史读取与已有会话发送均会使用目录缓存中的 `thread.path`。原实现未恢复已经失效的
JSONL 路径；尤其发送前的 `resumePermissionsFromRollout` 会先抛出 ENOENT，使
`thread/resume` 和消息发送都无法开始。截图对应电脑上文件为何失效尚未实机确认，
本修复以隔离数据复现并覆盖路径缓存、原生路径索引失效的情况。

现在发现路径失效后，先通过 `thread/read` 刷新只读元数据。必要时在配置的
Codex `sessions` 目录中寻找替代文件；文件名只用于筛选，首个 `session_meta.id`
必须精确匹配目标会话。拒绝符号链接和不明确的多个副本，不修改 Codex 文件或数据库。
恢复路径仅存 Relay 内存，首条元数据读取上限为 1 MiB。

原生历史索引也失效时，仅允许明确声明 `history_mode: legacy`、身份匹配且可完整
解析的本地历史作为恢复来源。分页存储的 JSONL 不能代替完整历史；原生分页接口
仍可独立返回历史时，保持该能力。权限错误与来源身份错误继续报错。

显式发送使用已校验的路径恢复同一会话，保留最后一个原生 turn context 的沙箱、
审批策略及写入根目录。恢复后缺少权限设置时停止发送；恢复响应的会话 ID 不符时
也不启动消息。普通发送、继续任务和显式设置更新共用该恢复入口。
历史读取不获取 writer；已有 Desktop owner 的消息路径沿用原逻辑。

## 验证

- 在修改前的 adapter 上运行新增回归，能够复现历史恢复和已有会话发送失败。
- Codex、历史读取、消息预算及会话 fork 相关回归共 411 项通过。
- 最后增加跨读取块的大型元数据头兼容后，路径恢复与权限恢复的定向检查 20 项通过。
- 修改的 JavaScript 文件通过 ESLint，`git diff --check` 通过。
- 用本机 CLI 在临时 `CODEX_HOME` 下生成协议 schema，确认 `thread/resume.path`
  对非运行会话可能覆盖 `threadId`，因此恢复路径和响应都校验会话身份。
  只读历史接口语义另参见 [官方 App Server 文档](https://learn.chatgpt.com/docs/app-server)。

所有会话、权限及路径样本均为临时目录中的合成数据。未启动、重启或重装本地
macOS 客户端，未使用真实账户执行模型任务，未发布或部署。真实故障电脑上的
手机打开历史、发送消息体验仍需在后续安装或发布获得授权后验收。
