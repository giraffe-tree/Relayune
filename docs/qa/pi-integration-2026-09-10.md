# Pi 实验接入与验收（2026-09-10）

本轮交付 Relay/Web 实验入口，固定 Pi 0.85.1。基础任务、审批与历史已实现，
**不代表现有全部 P0/P1 通过**。可行性映射见
Pi 核心用例评估（内部验收档案未随公开源码提供）。

## 开启与运行

先在本机为 Pi 配置可用模型与认证。Pi 所需 Node 为 22.19.0 或更新版本；
本轮真实 CLI 验证使用 22.19.0。适配器只接受 Pi 0.85.1，版本不符会拒绝启动。
不自动安装、升级全局 Pi，不复制或输出模型凭据。

- 独立 Relay 使用 `npm run relay:pi`，沿用现有安全连接环境。
- 多 Agent Relay 设置 `RELAY_ENABLE_PI=1`；`PI_BIN` 可指定 Pi 可执行文件。
- Pi 数据默认在 `~/.pi/agent`，可由 `PI_CODING_AGENT_DIR` 指定。
- Web 构建设置 `NEXT_PUBLIC_RELAY_ENABLE_PI=1` 可显示新建入口；已有 Pi 会话时也会显示。
  单 Agent Web 可用 `NEXT_PUBLIC_RELAY_ADAPTER=pi`。
- Desktop sidecar 已包含实验适配器，但本轮未增加 Desktop Pi 安装/登录按钮和手机专属入口。
  普通 Desktop 启动默认不启用 Pi；多 Agent 实验开关需由 Relay 启动环境传入。

受管会话由 Relayune 创建；已有原生 Pi 会话可读历史，但不直接接管写入。
受管进程关闭用户扩展、技能、提示模板和主题，只加载随 Relay 打包的审批/问题扩展。
不支持通过聊天执行 Pi slash 命令，也不提供无审批权限模式。

## 行为与边界

- `prompt` 接受不等于开始；`agent_start` 才发运行事件，`agent_settled` 才结束。
- 启动先占用会话，拒绝重复发送；停止启动中的任务不会继续发出 prompt。
- bash、write、edit 等有副作用工具必须获得一次性批准；不展示截断动作。
  超时、断连、拒绝和停止均失效，其他会话的审批保留。
- 停止先清队列和 abort，随后终止该 Pi 进程，隔离旧事件；下一轮从同一历史文件恢复。
- JSONL v3 只取当前树分支，保留压缩前可读消息；持久化 Relayune 消息/轮次 ID，
  合并同轮 assistant 内容，图片可经已有加密附件流程恢复。
- 同一受管会话用独占锁阻止第二个 Relay 写入。锁在子进程退出后释放。
  Relay 被强制杀死可能遗留锁，当前不自动抢占；必须先确认原 Relay 和 Pi 都已退出再处理。
- 工具审批不构成 OS 沙箱；本轮没有增加 Server 明文会话、凭据或工具日志。

真实模型图片理解、真实模型上下文恢复、手机通知与多端 P0/P1 全量验收。

## 证据分层

确定性测试：`npm run test:pi`，25 项通过，包含 RPC、适配器、真实 React 服务端渲染。
另外执行项目创建、MultiAgent 路由、账户排序、Web 审批约束与 E2EE 相关回归；
TypeScript 检查通过。隐藏实验 provider 时侧栏不会访问缺失选项，拖动仍映射到完整保存顺序。

真实 CLI：`scripts/test-pi-rpc-live.mjs`，Pi 0.85.1、Node 22.19.0，
使用隔离临时目录和本机脚本模型端点，最终运行耗时 5,387 ms：

| --- | --- | --- |

| 拒绝写入 | 文件不存在 | 通过 |

该测试执行真正的 Pi CLI、扩展和文件工具，但模型响应由本机夹具产生。
它不证明云模型、Web 操作、Desktop 安装或手机通知通过。未对真实账户消耗额度。
