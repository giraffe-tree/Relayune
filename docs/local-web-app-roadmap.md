# 加密访问电脑上的 Web 应用：演进方案

本方案记录 2026-09-25 的产品与架构取向。当前实现和限制见
[本地网页预览](local-web-preview.md)，设备结果见对应 QA 报告。
本文描述后续设计与验收门槛，不表示这些能力已实现，也不授权部署或发布。

## 目标与骨架

目标是 Android/iOS App 内可靠访问已授权电脑的本地 Web 应用，包含页面、API、
表单与会话。保留「手机 WebView → 手机本机网关 → E2EE → 电脑 Relay → 本地 Web 服务」。
已有 PAKE 授权、内容密钥与 Server 不接触会话明文的约束继续有效。

网页能加载不代表自动适配窄屏；响应式布局仍由站点负责。无需安装 App 的
Safari/Chrome 入口另行设计，不能复用 App 网关或让服务器解密代理网页。

字体异常是局部渲染故障。当前字体回退仅在检测到故障时工作，不是通用兼容性的基础。
不以持续增加网站特例、全局 API 覆写或 HTML/CSS/JS 字符串替换来扩展能力。

## 必须保留的语义

| 能力 | 设计要求 | 当前缺口 |
| --- | --- | --- |
| 来源 | 绑定电脑身份、授权与原始 scheme/host/port；不同来源维持隔离 | 单源；依赖字面 URL 重写，动态绝对 URL 有缺口 |
| HTTP | 保留方法、正文、状态码、头字段和重定向语义；错误可区分 | 请求/响应整体缓冲；大小与时限限制 |
| 会话 | Cookie 的 Domain/Path/Secure/HttpOnly/SameSite 与 JS 可见性；存储隔离 | 内存 jar 不提供 document.cookie；预览结束丢失会话 |
| 传输 | 并发、取消、分块、背压；页面关闭释放资源 | 持久命令适合控制与去重，不宜长期承载所有资源流 |
| 写入 | 断线时区分未发送、结果已知与结果未知；未知结果不能静默重发 | 已有命令去重不等于端到端业务 exactly-once |
| 依赖 | 站点明确声明并授权前端、API、WS 等 origin；逐源路由 | 尚不支持多端口、CDN、WS/SSE |

## 分阶段推进与退出条件

1. **完成当前单源基线验收。** 使用可重复的多页、模块脚本、字体、同源 API、
   原生表单和会话用例；补一套真实生产构建的 SPA。每次报告区分自检、UI 旅程、
   协议测试与设备平台。iOS 模拟器通过不能代替 iOS 真机或 Android。
2. **先验证来源与会话模型，再扩大授权。** 为每个原始 origin 保留独立的浏览器
   安全边界。通过实验确定 App 内来源映射方式，验证 location/origin、相对与动态
   绝对地址、Host/Origin、CORS、CSP/SRI、Cookie/CSRF、localStorage/IndexedDB、
   history 路由与重定向。不能把多个来源压成一个手机 origin。网关自身鉴权 Cookie
   必须与站点 Cookie 隔离，不能为支持 document.cookie 而暴露网关凭据。
   持久会话若引入，按电脑身份、授权主体及原始来源分区，允许清除、撤销失效；
   不复用电脑浏览器登录态。未通过这些实验前，不宣称一般登录应用可用。
3. **独立网页数据通道。** 控制面负责授权、目标与生命周期；数据面提供有界分块、
   并发、取消和背压，保持端到端加密。定义 request/stream ID、序号、总量上限、
   deadline、取消确认、断线与重连状态。比较 WebRTC 与密文中继路径的同一语义。
   不把所有资源流长久保存为任务命令。先做大文件、慢客户端、取消和断线故障注入。
4. **按授权依赖扩展。** 先前端+API 双端口，再 WebSocket/HMR、SSE、上传下载与
   CDN。新增目标必须明确归属与授权，限制回环/LAN/公网目的地；DNS、重定向、
   重连不能绕开检查。CDN 是否直接从手机访问或经电脑加密转发应显式设计，
   因其隐私、联网环境、Cookie 和 CORS 行为不同。
5. **复杂浏览器能力分开验收。** Worker、iframe、OAuth/第三方登录、媒体/设备权限、
   下载持久化分别立项；无覆盖项保持明确边界，不承诺任意网页无损兼容。

## 跨端验收矩阵

| 旅程 | 必须观察的结果 |
| --- | --- |
| 静态多页与生产 SPA | 子路径、返回/前进、hash/history、模块与资源加载；窄屏可用性单独记录 |
| API、表单、Cookie/CSRF | 中文及二进制正文完整、方法正确、303/307/308 语义、会话隔离 |
| 多 origin | 合法 CORS 正常；未经授权来源、端口和重定向被拒绝 |
| WS/SSE、上传下载 | 事件/字节顺序正确，有界内存；取消关闭，后台策略明确 |
| 断线与写入 | 发送前/发送后/响应丢失均注入；不悄悄重复业务写入，结果未知有明确反馈 |
| 平台与网络 | iOS 模拟器、iOS 真机、Android 分开；同网和跨网、直连和中继分别记录 |

每阶段以明确的能力和失败语义收口。测试站点数量只帮助扩大样本，不能替代来源隔离、
会话和传输正确性；当前单源版本也不应因一次示例成功被称为完整通用代理。
