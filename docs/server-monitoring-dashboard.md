# 服务端监控网页

入口 `/monitoring/`，数据接口 `GET /api/monitoring`。独立页面复用 Relayune 的邮箱密码登录与
HttpOnly 会话 Cookie，只允许服务端 `MONITOR_ADMIN_EMAIL` 显式配置的管理员账户；未配置时拒绝所有账户。
服务端在读取缓存、SLS 或 MongoDB 前校验已经验证的邮箱会话：匿名 401，其他账户 403。
不接受客户端邮箱、Authorization 或身份 header 作为监控授权依据，不改变普通用户的 Relayune 登录权限。
静态页面壳不包含任何监控数据，所有实际数据均经过服务端授权返回，响应 no-store。

页面提供 15 分钟 / 1 小时 / 6 小时 / 24 小时视图、30 秒自动刷新、完整 user_ref 筛选、
API 请求量、5xx 比例、P95/P99、按 user_ref 近似去重用户数、流量与耗时趋势、接口排行和最近 50 条错误。
耗时兼容无版本秒单位及 v2 毫秒单位。健康探测和监控接口本身不计入业务 API 汇总。
无数据时保留空状态，SLS 不可用或查询未完成时返回错误，不把失败转换为零请求。

运行状态来自当前 API 进程及其所在主机：MongoDB ping、API RSS/运行时长、主机内存使用率、
1 分钟负载和 CPU 核数。负载不等同于 CPU 使用率。最近日志时间用于发现入库延迟，
不代表长时间可用性保证。SLS 数据存在采集延迟，API 缓存 30 秒，同参数并发合并。
图表按 60 个时间桶聚合；接口表在请求量前 30 个接口中排序。所有 SQL 模板固定，
浏览器不能提交 SQL、任意时间跨度或其他 Project/Logstore。仅返回白名单字段。

## 配置与上线

以下为配置示例，不代表已经部署。服务器通过受限环境文件配置：

```dotenv
MONITOR_ADMIN_EMAIL=admin@example.com
SLS_READ_CREDENTIALS_FILE=/etc/agent-relay/sls-read-credentials.json
SLS_PROJECT=your-project
SLS_LOGSTORE=your-logstore
SLS_REGION=cn-your-region
```

该 JSON 文件使用 `access_key_id`、`access_key_secret` 和可选 `security_token`，
要求 root/服务用户所有，root:agent-relay 0640 或服务用户 0600，拒绝符号链接与宽松权限。
使用只允许查询所配置 Project/Logstore 的 RAM 凭据；不要使用浏览器变量或 NEXT_PUBLIC 配置，
不要把凭据正文提交到 Git。既有采集器 ECS 自动认证负责写入，不会自动赋予 Node 查询权限。
SLS 目标由这三个标识构造，服务端校验名称并固定使用阿里云 HTTPS 域名，不接受任意 URL。
默认使用所配置地域的内网 HTTPS；需要公共端点时设置 `SLS_USE_PUBLIC_ENDPOINT=1`。
未配置管理员时，已登录账户得到 403；配置管理员但未配置凭据文件时，管理员得到 503。
启用凭据文件时必须同时设置有效的三个 SLS 标识，否则启动时报配置错误。
更改配置后重启服务；普通用户登录权限不受监控授权影响。页面登录表单允许输入管理员邮箱，
管理员账户仍需通过既有注册、邮箱验证和密码设置流程建立，配置本身不创建账户。

上线按现有 Web/API 候选健康验证、原子切换和回滚流程执行。无需数据库结构变更。
`/api/monitoring` 的访问日志暂使用安全的 unmatched 路由标签，因此不进入自身业务 API 统计；
若以后新增固定标签，须同步生产采集配置，且仍应从业务汇总排除监控请求。

签名协议依据[阿里云 SLS 官方请求签名说明](https://help.aliyun.com/zh/sls/developer-reference/request-signatures)。
SLS GET 查询需在部署环境独立验证；原始响应不得写入文档或浏览器静态产物。

## 验证边界

公开副本不提供真实 SLS 查询、生产用户或上线主机的验收记录。需在目标环境分别验证权限拒绝、凭据权限、固定 SQL、数据一致性、空结果、错误恢复和页面布局；构建成功不等同监控可用。

## 接口筛选

支持按请求方法和固定接口路径组合筛选，也可选择全部方法/全部接口。筛选同时作用于
请求总量、错误率、延迟分位数、趋势、接口表和错误列表，并可叠加时间范围及 user_ref。
接口选项来自完整路由白名单，不依赖当前排行前 30 名；无数据的组合显示空结果。
服务端验证方法及路径白名单，拒绝任意 SQL/路径输入；不同组合使用独立缓存。
主机运行指标和日志入库新鲜度始终反映整个服务。

## 最近用户与邮箱搜索

管理员页按最近 120 天 SLS 日志的最后请求时间排序展示最多 100 个 user_ref，
用服务器日志专用 HMAC 密钥计算 MongoDB `auth_users._id`（规范化邮箱）的引用并匹配。
读取数据库时仅投影 `_id`，使用只读游标、10 秒查询时限，找到目标后提前停止；不读取密码或 token。
匹配结果只在进程缓存中保存 60 秒，不新增持久化映射表；邮箱仅返回给指定管理员。
账户删除或日志密钥轮换后无法用当前密钥匹配的引用保留，并显示无法关联邮箱，不猜测身份。

`POST /api/monitoring/resolve-user` 接受单个完整邮箱，需要已经验证的管理员会话和同源 Origin。
邮箱只出现在 POST body，转换为 user_ref 后由浏览器使用原监控查询接口筛选；邮箱不发送到 SLS，
不进入 URL、请求日志或持久化映射。可搜索不在最近 100 人列表中的邮箱；无匹配日志显示空结果。
搜索和点击用户后自动选择 120 天并清除接口过滤，避免旧过滤导致误判无记录，再可缩小范围。

增加 7 天、30 天、120 天范围；请求记录默认展示最近 100 条所有状态的请求，
包括成功响应的 HTTP 状态、毫秒耗时与 trace_id，可切换为最近 50 条错误。
这里的响应信息只指状态和耗时，不展示请求体、响应体或端到端加密的会话内容。

历史邮箱搜索上线与真实用户核对结果留在私有维护仓库，未随公开源码提供。

## 客户端版本

用户列表分别展示 macOS、手机（iOS / Android）及 Web 最近上报的版本和服务器接收时间。
版本来自认证成功请求的 `X-Relay-Client-Version` / `X-Relay-Client-Platform` 公开元数据，
不以服务器部署版本推断客户端版本；同平台多设备时显示最近上报值，不代表所有设备都已升级。
旧客户端没有完整上报时显示“暂无记录”，升级后再次请求自动补齐；不按授权设备名称猜测平台。
MongoDB 每账户每平台只保存一个值，同版本写入最多每分钟一次；版本变化立即更新。
该元数据不写入 SLS，不返回账户密码、令牌或业务内容，仍仅服务端配置的管理员可读取。

真实生产客户端版本观测与发布记录留在私有维护仓库；此处只描述数据归属与功能，不声明公开副本已上线验收。
