# WebRTC 会话直连

手机 App「设置 → 连接链路」提供「自动选择（推荐）」与「服务器中转」。设置沿用原有
`relayune.direct-reads.v1` 本地偏好键：未设置时默认自动；已明确选择服务器的用户保持原选择。

## 覆盖范围

- 发消息（包括附件上传）、审批、停止生成、配置会话、创建会话与 Agent。
- 项目操作、历史、附件与 Agent 信息读取。
- 实时会话事件：用户消息、生成增量、审批与执行状态。

登录、独立 PAKE 授权、设备在线状态、目录发现、撤销同步和 SDP 协商仍依赖服务器。
直连的会话事件不重复上传服务器；后台或离线时回退原有服务器事件和推送流程。

自动模式要求 Desktop 宣告加密能力 `webrtc-auto-v1`（同时保留 `webrtc-session-v2`），使用可靠、有序的
`relayune-session-v2` DataChannel。不会把旧 Desktop 的只读支持误认为完整会话支持。
两端继续验证原有 A256GCM envelope；DataChannel 的 DTLS 加密不替代应用端到端加密。

## 自动检测

App 在前台运行时独立检测，不依赖业务请求触发。每次建链最多 30 秒（包含协商、探测、同步与激活），
超时关闭该次连接并继续服务器传输。诊断只记录固定阶段名、耗时和结果，不记录地址、标识或载荷。验证期间业务继续走服务器；依次完成
加密 nonce ping/pong、事件 resume 与服务器补齐、activate 确认、激活后再次 ping，才将
会话链路标为直连。仅 ICE/DataChannel 建立成功不足以切换。旧 Desktop 留在服务器链路。

直连空闲时每 15 秒发送一次加密探测，响应超时 4 秒即关闭直连并回退。传输忙时跳过
该轮探测，避免把附件排队误判成故障；业务请求仍有原有 20 秒超时和事件 10 秒确认期限。
Desktop 为传输控制保留每连接 4 个在途名额，不占业务请求名额。

失败后按 15、30、60、120 秒递增重试，增加 0–20% 随机延迟；连续四轮健康探测后才
清除失败退避，避免网络抖动时反复切换。可以点击「立即检测」跳过当前等待。
App 进入系统后台、锁屏、退出或强制服务器模式时停止检测并关闭直连；回前台重新验证。
这里的后台检测指前台运行期间的异步任务，不依赖 iOS 后台常驻能力。

## 切换与恢复

建链后先执行加密的 resume/activate 同步：Desktop 暂存新事件并排空旧 HTTPS 上传，
手机从原有服务器 cursor 补齐旧事件，随后激活直连事件。服务器 cursor 与 Desktop
事件序号不混用；同一事件经过不同链路仍保留同一 event_id，由现有手机 reducer 去重。

事件先写入 Desktop 加密 outbox。仅收到对应连接、接收方、event_id、event_seq 的
加密确认后，才移除该客户端副本。其他客户端副本继续独立投递。连接断开或事件实际发送后 10 秒内
未确认时，原密文回退 HTTPS；进程重启仍可从 outbox 重放。

准备切换期间尚未发送的事件不启动 ACK 倒计时，避免较慢的 HTTPS 补齐被误判成直连故障。

写命令在两条链路共用的入口登记持久化执行记录，保留至命令过期。同一请求编号只能
对应同一客户端与命令摘要。直连确认丢失时，手机通过 HTTPS 重发**原始编号和密文**，
Desktop 复用已有执行记录及加密响应，避免重复发送消息、批准动作或创建资源。
只读请求可用新编号重试。直连请求最长等待 20 秒后回退；明确断线时提前回退。

这不是跨 Agent 的事务性 exactly-once：若 Desktop 在登记后、实际执行结果确认前崩溃，
不会盲目重做写操作，客户端可能需要核实会话状态。命令成功送达也不等于 Agent 已执行成功。

## 资源与安全边界

- 两端分片每块 12000 个字符，最大密文帧 44 MiB；发送队列具有背压。
- Desktop 最多 8 个客户端、每连接 4 个在途请求；事件待确认队列最多 256 条。
- 执行记录最多 1000 条未过期记录；加密结果缓存合计 16 MiB，超过时结果走 HTTPS。
- 每客户端每分钟最多 6 次协商，全局 40 次；只允许 DataChannel，拒绝音视频 SDP。
- 身份撤销、控制连接断开或授权快照超过 45 秒时关闭直连。
- 当前只配置 STUN，不使用 TURN。无法穿透的网络继续使用原服务器；公网跨运营商尚未实测。
- SDP、ICE 地址、命令、附件、会话密文解密结果不写日志。

## 验证

`tests/webrtc-transport.test.mjs` 使用真实 Node WebRTC peer 验证分片、路由与有效期、
撤销、持久化去重、重启后重试、审批验证器、事件确认、断线补发及切换同步屏障。

`mobile/integration_test/webrtc_read_test.dart` 配合仅绑定 loopback 的
`tests/fixtures/webrtc-mobile-server.mjs` 使用原生 iOS WebRTC，验证：

- 大历史和真实 PNG 附件读取走直连。
- 大消息上传、审批及实时事件绕过 HTTP 会话载荷传输。
- 配置操作执行后强制断线，HTTPS 恢复结果且不重复执行。
- App 切换链路时读取恢复，以及对端断开后的自动回退与自动重连。
- 连接保持打开但探测无响应时回退；拒绝错误 nonce；恢复后无业务请求也能自动直连。
- 强制服务器模式不会继续探测。

相关加密、server blindness、outbox、远程命令、手机控制器和设置测试另行覆盖原有行为。
此验收使用合成密钥、合成会话与可控适配器，不代表公网 NAT 穿透率或真实 Agent 全旅程验收。
