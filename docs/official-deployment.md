# 官方服务与客户端联合升级准备

更新：2026-10-22。官方版使用本公开仓库的同一份源码，部署到 `relayune.giraffetree.cn`；
自托管用户名模式仍保留。本文件记录实施与验收范围；实际操作以维护者在当前任务中的明确授权为准。

## 已确定边界

- 官方首轮升级不要求兼容旧客户端；按同一候选版本验证并协调升级服务端、macOS、Android、iOS。
- 不新增旧权益接口的兼容响应，不恢复支付、订阅、兑换码或审核演示模块。
- 旧客户端在切换后可能无法使用，需更换新客户端；允许按需要重新登录和配对。
- 不兼容旧客户端不等于清空数据：既有数据库、blob、签名身份和私钥默认保留，删除或重建另行明确。
- macOS/Android 使用原官方签名身份以支持正常安装升级；iOS 首轮仍按 TestFlight 公开测试准备。
- 维护者已允许本地首次提交，暂不 push。正式构建记录真实来源提交。
- 先完成本机与测试环境验收，再允许 macOS 正式签名并替换安装、Android 签名、TestFlight 上传、官网/OSS 安装包发布，以及官方 Web/API 切换；保留旧版本回滚。
- 本轮移动端使用 iOS 模拟器，不使用真实手机。Android 安装、真实手机权限及后台行为保留为未验收，不能以模拟器或构建结果替代。
- 允许短暂停服和重启。真实 Codex、Claude Code、Kimi Code 只在独立临时项目中执行合成任务；测试邮箱仅保存在仓库外或忽略的私密验收配置。

## 官方部署配置

从 [.env.official.example](../.env.official.example) 创建仓库外的受限配置，使用
`RELAY_AUTH_MODE=email`、官方 HTTPS 域名与自己的 SMTP。实际数据库、运行账户、文件和 Node
路径先按现有部署核对，不能直接把示例路径覆盖到服务器。

不配置用户名模式的 HTTP 初始化令牌，不运行 `prepare-self-hosted.mjs` 或 `local-account.cjs initialize`。
官方站点复用经预检确认的受信域名证书，不引入自托管私有 CA。敏感配置不进入客户端编译变量或 Git。
配置由进程管理器注入；`npm start` 不会自动读取此模板。

## 实施顺序

1. **整理本地候选版本。** 保留公开仓库作为主干；核对三个平台版本、构建号和新发布说明，
   不复用旧 `0.3.32` 安装包作为新源码验收证据，不覆盖已存在的版本化发行文件。
   先完成候选内容检查和本地首次提交，再使用真实 HEAD 构建；不伪造提交编号或绕过正式发行来源校验。
2. **完成分发前检查。** 处理 Web `client-only@0.0.1` 的实际产物与许可证据缺口；
   原生包核对 Node/pkg、Rust、Flutter 等实际包含组件的许可。参见[许可说明](licensing.md)。
3. **只读预检现有服务器。** 核对域名指向、TLS、Nginx、Node/系统运行时兼容性、服务用户、
   端口、磁盘、数据库认证、目录和旧版本指针。记录可回滚位置，不直接修改现有站点。
4. **备份并准备隔离候选。** 生产数据与配置保留；候选使用独立数据库、私有 blob 和未占用的
   loopback 端口，以合成账户验证，避免候选启动时对生产库建立或修改索引。
5. **构建并验证新版本。** 构建静态 Web/API 和新客户端；检查官方邮箱登录、Mac 账户确认、
   扫码配对、真实 Agent 任务、审批/回答/停止、断网与前台恢复、撤销。三个重点 Agent 分别记录支持边界。
   旧权益接口继续不提供，不为通过测试临时引入旧收费门禁。
6. **验收通过后联合切换。** 提前准备可安装的新客户端，再协调官方 API/Web 与客户端升级。
   使用新的版本目录，验证后切换；不修改其他站点，不重建数据库，不提前更新未上传安装包的下载清单。
7. **公网验收与回滚。** 检查 HTTPS、首页/深层页面、邮箱登录、配对、任务和日志；失败恢复上一份
   Web/API 指针。数据保持原状；若涉及不可逆数据变更，需独立设计迁移与回滚，不能把代码回滚视为数据回滚。
