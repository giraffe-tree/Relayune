# macOS 保持唤醒与防止自动锁屏

菜单栏“保持唤醒 → 保持唤醒时，不自动锁屏”与“设置 → 通用”使用同一份偏好。
模式和选项按用户选择保存，菜单状态依据实际电源断言显示。

## 行为

- 关闭保持唤醒：释放本进程的系统与显示器断言。
- 仅插电：插电时生效，拔电后释放；始终模式也在电池供电时生效。
- 勾选防锁屏：在保持唤醒生效时，同时阻止系统闲置睡眠和显示器闲置睡眠。
- 未勾选：只保持电脑运行，允许显示器正常闲置。
- 暂时关闭唤醒或拔电不会清除勾选偏好；再次生效时恢复该选择。
- 关闭窗口后继续运行，退出应用释放自身断言；重启后按已保存偏好恢复。

此功能不自动解锁屏幕，不阻止手动锁屏、合盖或手动睡眠，也不覆盖设备管理策略。
不能将它描述为任何环境下“永不锁屏”。

## 实现与本地状态

Rust 使用公开 IOKit `IOPMAssertionCreateWithDescription`，与 `caffeinate -di` 对应的
`PreventUserIdleSystemSleep` 和 `PreventUserIdleDisplaySleep` 断言相同，不启动 caffeinate 子进程。
不使用 `UserIsActive`、不模拟键鼠、不修改系统密码、屏保时间或 pmset 设置。

运行时定期核对断言的类型、名称与等级；失效时恢复，无法确认时保留原 ID 并报告未确认，
避免反复新建断言。`lock_prevention_active` 表示两种断言已核实，不代表实际屏幕处于解锁状态。
菜单使用标准勾选和状态标记；未生效、关闭未完成或等待电源时显示对应状态。

偏好保存在本机 `keep-awake.json`，支持旧字符串模式迁移到包含 `mode`、`prevent_lock` 的对象。
保存失败保留旧状态；断言失败可重试。该文件属于本机运行状态，不进入 Git 或公开源码包。

## 验证范围

历史工程检查覆盖偏好兼容、模式联动、插电状态、失败重试、断言释放、菜单状态和语言文案；
受控 macOS 测试确认过实际系统/显示器断言的创建、释放及恢复，设置页也做过有限交互检查。
这些记录不构成所有系统策略、硬件和客户端升级组合的完整验收。

实际菜单栏直接点击、长时间闲置，以及指定屏保超时和密码宽限条件下的原生对照仍未完整覆盖。
不得用断言存在或短时安装检查代替这些场景的结果。本说明不记录维护者个人机器的当前安全设置、
Agent 登录状态或电源偏好。
