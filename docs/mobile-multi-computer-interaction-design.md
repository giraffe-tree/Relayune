# 手机端多电脑交互重设计

> 2026-09-28 用户标注修订：页面展示与交互以 [模拟器核查与设计修订](mobile-ui-simulator-review.md) 为准。首页及对话页不展示电脑名称；抽屉横向滑动点选电脑；设备列表增加 SVG，详情保留模拟器现状；添加电脑直接扫码。本文下方与这些视觉规则冲突的早期方案不再适用。
状态：交互方案，尚未替换正式 App。2026-09-28。

页面结构已在实机核查后修订，以 [手机端现状核查与设计修订](mobile-ui-simulator-review.md) 为准。前两版通用 HTML 原型不再作为视觉基准；本文中的任务归属和状态规则继续有效。

## 目标与边界

用户始终知道正在看哪台电脑、哪个 Agent，以及下一次操作会发给谁。
保持「用户 → 电脑 → Agent → 任务」；项目是电脑内已有的任务组织方式。
复用现有账户、电脑、Agent、任务、授权，不引入工作空间、连接组、主电脑等业务实体。
本轮设计覆盖手机端导航、电脑切换、添加、任务、离线和通知。保留已有独立授权与端到端加密。

## 当前结构的问题

根据当前代码，而非只根据“添加响应慢”推断：

- `RelayuneReadyScreen._selectedComputer` 默认 null，代表所有电脑，但 `_homeController` 回退到第一台 ready 电脑。总览和单机上下文共存，连接指示、问候、抽屉及部分操作可能来自不同范围。
- 首页和抽屉有电脑下拉框；进入 `WorkbenchScreen` 时没有传入电脑管理器，任务页没有相同的切换能力。
- 添加入口位于 `DevicePage` 的设备信息和安全说明之后；只有一台电脑时不展示电脑列表，用户难以建立稳定的入口记忆。
- `_openPendingNotification` 依赖任务已在本地列表中；任务未同步时没有明确的加载或失败落点。
- 草稿、阅读位置按 controller 实例保留。重建连接、重新授权后的稳定身份和恢复行为需要明确，不能仅依赖对象还存活。

## 页面与入口

### 1. 常驻的电脑入口

首页、任务列表、对话页顶部显示「电脑名 ▾」和该电脑的连接状态。点名称打开同一个电脑面板。
单电脑时仍保留这个入口，提供添加和管理；不展示没有选择意义的单选下拉框。
抽屉顶部复用这个入口，下方继续放当前电脑的 Agent、项目和任务。
不增加底部导航栏，不同时保留多套含义不同的电脑选择器。

电脑面板内容：

1. 已添加电脑：名称、在线/连接中/离线/需要重新授权、当前选中标识；有待处理任务时显示数量。
2. 「添加电脑」始终可见，位于列表之后；电脑较多时该操作固定在面板底部。
3. 「所有电脑的任务」作为次级入口。
4. 每台电脑的详情入口进入该电脑详情；诊断与移除在详情内。

列表保持稳定顺序，不因上线、离线和任务变化重新排序。同名电脑用已有系统信息或设备标识的非敏感短后缀区分。
点电脑行切换；点详情按钮只打开详情。两者有独立触摸和无障碍目标。

### 2. 默认打开一台确定的电脑

- 首次添加成功：进入新电脑任务列表。
- 再次打开 App：恢复上次明确使用的电脑，以及该电脑的 Agent、项目筛选。
- 上次电脑离线：仍显示这台电脑和离线状态，不自动跳到另一台在线电脑。
- 上次电脑已被移除：只有一台剩余时进入它；多台时打开选择面板；没有电脑时显示添加引导。
- 各电脑独立恢复连接；一台连接失败不阻塞其他电脑，也不阻塞电脑面板。
- 用户主动选择总览后可记住这个浏览位置；首次启动和新增第二台电脑不会自动变成总览。

### 3. 电脑内的任务与 Agent

列表顶层是当前电脑；Agent 使用已有切换控件，显示本机可用的 Agent。项目筛选随电脑和 Agent 保留。
默认恢复上次 Agent；首次有多个可用 Agent 时选择已有产品默认值并明确展示，只有一个时省略选择步骤。
Agent 未登录显示「需要在这台电脑登录」，保留旧任务阅读，禁用依赖该 Agent 的执行操作。
电脑在线与 Agent 可用分别呈现，不能把电脑在线等同于 Agent 可执行。

新任务沿用「当前电脑 + 当前 Agent + 当前项目」。输入区上方显示执行位置；不增加常规确认弹窗。
在新任务尚未发送时更换电脑/Agent，保留原位置草稿并载入目标位置自己的草稿，不把内容或路径自动搬过去。
已经存在的任务固定所属电脑和 Agent；界面不提供原地把任务改到另一台电脑的假象。

### 4. 跨电脑总览

明确标题「所有电脑的任务」，状态显示「2/3 台在线」等汇总，不引用任意一台电脑的在线状态、用量或路径。
每条任务必须显示电脑与 Agent；保留待处理、运行中、未读和最近任务，并可继续加载，不能静默只显示固定数量后没有入口。
点击任务进入它自己的电脑与 Agent，返回回到原总览位置。
总览里的「新任务」先选择电脑，再进入该电脑的新任务页；绝不默认落到第一台 ready 电脑。
总览不提供无目标的审批、终止等执行动作；这些动作进入有明确归属的任务后进行。

## 切换规则

主动切换电脑固定落在目标电脑的任务列表，恢复目标电脑上次 Agent、项目和列表位置。
不突然打开目标电脑上次的旧对话。点任务才进入对话。
切回原电脑后，任务仍在原列表，打开后恢复草稿与阅读位置。
切换不发起登录、配对、断开或取消任务；也不等待目标电脑完成网络连接。

| 场景 | 界面反馈 | 后台行为 |
| --- | --- | --- |
| A 对话有未发送文字，切 B | 进入 B 列表；必要时轻提示“草稿已保留在 A” | A 草稿按任务存储，绝不带入 B |
| A 有运行任务，切 B | B 面板仍可见 A 的运行/待处理数量 | A 继续运行、接收事件和通知 |
| 切到离线 B | 立即显示 B 名称、缓存和离线横幅 | 自动重连，可手动重试；不代选 A |
| 快速 A→B→C | 最终停留 C，标题与列表同步更新 | A/B 的迟到结果只更新自己的缓存 |
| A 审批提交后切 B | B 正常可操作；A 行更新提交状态 | 审批捕获 A 的任务和授权，不读新选择 |
| 发送时连接中断 | 在原任务显示发送中/未确认及恢复动作 | 不盲目自动重发；按已有请求标识核对结果 |
| 从通知打开 B，原来在 A | 立即进入标有 B 的目标任务加载页 | 保存 A 导航来源；返回可恢复 A |

主动电脑切换替换当前浏览分支，不把 A、B、C 逐个压进返回栈。通知与总览任务跳转则保留一个明确的来源。
冷启动通知没有来源时，返回目标电脑任务列表。显式切换电脑后，旧通知来源不继续影响返回。
电脑面板、添加和详情页面的返回只关闭当前页面，不隐式改变电脑。

## 添加电脑

点击后立即进入添加页；账号检查、发现电脑和网络初始化在页面内进行，全部有进度和取消入口。
文案明确「在要添加的电脑打开 Relayune，输入电脑显示的 8 位授权码」。复用已有配对方式，不修改 PAKE。
若展示账户内电脑候选，候选只代表可选择目标，不代表已获得访问 Agent 的授权。

状态顺序：输入/准备 → 验证授权 → 建立连接 → 可使用。

- 代码错误/过期：保留页面，说明原因并允许重输，不清除原电脑。
- 网络暂不可用：保留当前步骤，允许重试和返回；不无限显示没有说明的转圈。
- 成功：展示电脑名，进入新电脑任务列表。账号无权使用时给出对应账户处理入口。
- 用户取消：回到原浏览位置。取消后的迟到成功回调不能偷偷添加电脑或抢占页面。
- 重复点击添加：打开现有流程，不能产生多个并行配对页面。
- 已存在相同电脑且授权有效：提示“这台电脑已添加”，提供前往，不生成重复行。
- 同电脑重新授权：验证新授权成功后才替换旧授权；失败不移除原电脑。旧授权通知失效，但历史和草稿按安全规则处理。
- “正在添加”只属于临时页面状态，不成为持久业务实体；中途退出的暂存授权按现有清理规则收尾。

## 离线、授权与移除

| 状态 | 用户看到 | 可执行操作 |
| --- | --- | --- |
| 连接中 | 电脑名、连接中、已有缓存 | 切换、查看缓存、管理；需实时连接的动作禁用 |
| 在线 | 本机连接状态、各 Agent 状态 | 仅可用 Agent 的执行操作 |
| 离线 | 最后同步时间，说明内容可能不是最新 | 阅读缓存、编辑本地草稿、重连、切换；发送/审批禁用 |
| 需要重新授权 | 原电脑仍在列表，原因与重新授权按钮 | 授权、切换、移除；按已有密钥策略决定历史可读性 |
| 手机网络不可用 | 全局网络提示 + 原有电脑列表 | 保留浏览上下文；不误称所有电脑已撤销授权 |

移除放在电脑详情底部，二次确认明确名称及影响：删除本手机对该电脑的连接和本地授权，不会删除电脑上的任务或停止 Agent。
若草稿会随本地清理丢失，确认内列明未发送草稿数量并允许取消；不能承诺保留实际无法解密的历史。
移除当前电脑后按“恢复默认电脑”规则选择落点；移除后台电脑不打断当前任务。
账号退出属于全局操作，放账号设置，不放某台电脑的连接状态菜单；沿用现有安全清理策略。

## 通知与后台恢复

通知使用既有「电脑 ID + 授权 ID + 任务 ID」定位，不读取当前电脑作为默认值。
点击后立即有带目标电脑名的页面；任务未在列表时主动获取该任务/刷新该电脑目录。
明确处理：正在同步、电脑离线、授权失效、任务不存在、电脑已从本手机移除；提供重试、重新授权或返回。
旧授权通知不能映射为新授权上的审批；Android 通知动作同样验证目标和当前待审批状态。
切电脑不重复申请推送权限，不注销其他电脑 token 绑定，不因不同电脑同名或相同原生任务 ID 串通知。
保留上一版 Android 服务端同账户一 token 对多电脑的兼容结构；本次导航设计不需要新增服务端实体或协议。
如现有客户端缺少按任务加载入口，优先复用目录刷新和现有会话 API；协议扩展需另行验证必要性。

## 最小实现结构

继续使用 `ComputerConnections` 管理电脑连接，每台电脑一个 `AppController`；不另建业务对象体系。
在现有导航宿主内集中管理选择和返回，不让首页、抽屉、对话、通知分别选电脑。

- 选中的稳定电脑 ID：驱动导航与持久偏好；总览用显式视图类型，禁止 null 同时表示总览和默认电脑。
- 每台电脑的浏览偏好：Agent、项目、列表位置。每个任务的草稿/阅读位置使用账户、电脑、Agent、原生任务 ID 组合，避免碰撞。
- 活动对话路由：固定电脑 ID、授权版本、Agent、任务 ID，不能由可变 selectedComputer 间接解析执行目标。
- 通知来源和添加步骤：仅路由/流程状态；没有新表，没有独立业务实体。
- 本地展示元数据：电脑名称和最后同步时间，供离线启动展示；不混入凭据或服务端会话明文。
- 授权版本用于拒绝迟到请求与旧通知；草稿是否延续到新授权必须同时核对账户、电脑和现有存储安全策略。

所有异步工作捕获目标与本次操作版本。取消、退出、移除、切换后的结果可以更新有效目标的缓存，但不能改当前路由或执行另一个目标的动作。
新请求不重用另一台电脑的项目路径、附件、终端或 Web 预览 URL；各功能继续绑定任务所属电脑。

建议一次完成基础导航替换再验收，不把旧选择器和新入口长期混用。内部实现按三步推进：

1. 集中导航归属和电脑面板，覆盖首页、抽屉、任务与新任务；保持已有连接协议。
2. 补齐添加/取消、离线恢复、稳定草稿和通知目标加载，统一状态文案。
3. 删除旧分散入口；执行下列验收，完成本地签名 macOS 和独占 iOS 模拟器安装验收。

## 必须通过的交互验收

1. 只有一台电脑时，首页和对话页均能进入添加；点击立即看到页面，网络慢不会卡住导航。
2. A 草稿 + A 运行任务 → B 新任务 → A 原任务：草稿和阅读位置恢复，运行不中断，项目/附件不串。
3. A/B 同名且任务原生 ID 相同：列表可区分，发送、审批、通知各归其主。
4. A→B→C 连续切换，叠加 A/B 迟到返回：最终标题、Agent、任务列表和发送对象始终一致。
5. 上次电脑离线、手机断网、某 Agent 未登录：各自显示准确状态，其他电脑可用。
6. 添加取消、失败重试、重复点击、添加已存在电脑：没有幽灵电脑、重复行或页面抢占。
7. 从 A 草稿打开 B 通知，B 任务尚未同步：显示加载/失败落点；返回 A 草稿仍在。
8. 后台电脑离线、授权撤销、移除：不把旧通知动作发给当前电脑，不静默丢弃用户点击。
9. 移除当前/后台电脑、移除最后一台、退出再登录：落点与本地清理符合规则。
10. 冷启动分别延迟各电脑恢复：所有入口可响应；选择不因哪台先上线而改变。
11. iOS/Android 返回手势、键盘、屏幕阅读器、大字体、小屏幕：切换和取消可达，不遮挡主要操作。
12. Android 同一手机接收两台电脑通知：切换不修改注册，多电脑推送与审批动作仍正确。

本文件定义目标行为，不代表上述验收已完成。上一轮添加延迟修补仍是未提交工作，不能当作本次整体重设计已经上线。
