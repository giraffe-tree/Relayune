# 在线密文投递与数据库容量

目标：100 个用户同时使用时，Relayune 的数据库读写不随流式片段数量增长，并将运行中
单个 Node 服务发起的 MongoDB 操作控制在每个滚动一秒的预算内。100 个用户不能单独
定义负载：验收同时记录在线客户端数、每秒事件/查询/写命令、载荷大小、失败和延迟。

## 数据归属

- MongoDB 保存账户、设备、独立授权、必须持久接受的命令、通知任务和旧客户端中转。
- Desktop/Agent 保存完整会话历史。新客户端的在线事件、只读查询和响应通过
  `/api/stream` 的 WSS 转发；WebRTC 可用时仍可直连。容量验收不依赖 WebRTC。
- 人工写操作继续走持久 HTTPS 命令路径，共享现有执行记录；重试不能换请求编号。
- Node 不积攒离线载荷，不解密会话数据。路由只使用经过鉴权的设备、独立客户端和连接代次。
- 大于通道上限的查询响应使用现有 HTTPS/私有 blob 回退，保持请求编号及密文绑定。

只读 WSS 请求发出 500ms 后仍未完成时，Web/手机通过既有响应接口取回同一请求编号的
HTTP 响应，并与 WSS 响应竞争完成；此步骤不提交第二条命令。两条路径共用原请求的
8 秒截止时间，完整校验路由、AAD 和解密正文后才接受结果，单条路径失败不取消另一条。
完成或截止时取消 HTTP 请求和 WSS pending，释放等待资源。原响应均未成功取回时，
才沿用独立编号、重新加密的只读 HTTP 重试；写操作不进入此恢复分支。
这样 Relay 因发送缓冲拥堵转存 HTTP 后，客户端无需盲等 WSS 的完整超时。

## 协商、授权和活性

Server hello/bootstrap 声明 `online_transport_version: 1`；客户端还必须验证 Desktop
加密 catalog 声明 `online-stream-v1`。缺少任一能力时继续既有协议。

新通道的第一条消息是 `hello`，角色为 `relay` 或 `browser`。Desktop 传设备令牌；
浏览器/手机使用邮箱会话和独立客户端令牌。令牌不进入 URL 或日志。Server 返回随机
`connection_id`，浏览器获得对应 `browser_id`。后续 `frame` 的内层仍为原有 A256GCM
envelope，校验 AAD、密钥标识、方向、设备、客户端、请求和期限；客户端仍必须解密验证。

每 10 秒由业务事件循环发送 `renew`，30 秒未续租即失效；TCP Pong 不代替续租。
权限每 30 秒复核，同一连接只有一个在途复核，超过 45 秒未验证即关闭。账户会话、
设备撤销和独立授权均重新检查；配对撤销立即切断相关连接。鉴权开销与连接数有关，
每条业务消息不再重复查询数据库。

Server 每 10 秒及订阅变化时向 Desktop 推送带期限的订阅快照。Desktop 同样检查期限
和控制通道的授权新鲜度；丢失离线通知也会到期停止生成副本。连接实例替换后，旧连接
关闭或迟到回执不得操作新实例。当前订阅表只存在内存；重启后重新连接、重新授权。

旧通知 WebSocket 与新通道同时存在时，旧连接必须标记为不参与投递，防止新通道失联
后被旧连接误判在线。客户端进入新通道模式后也关闭旧通知连接。

## 背压与恢复

Desktop 只为有效订阅或有效直连生成实时事件副本。每个在线接收端最多 64 条或
256 KiB 未确认事件，达到任一上限暂停；有待确认数据而 10 秒无消费进展也暂停。
有效的加密 `transport.event_ack` 必须匹配客户端、连接代次、事件 ID 和序号。
服务器转发或 socket.send 成功不构成消费确认。

在线事件与离线通知的本机副本还有总字节上限。未确认在线副本带本机 `online_only`
标记，断线和进程重启后不能静默转为 MongoDB 上传。事件最多 10 分钟，响应最多
5 分钟；重试不刷新创建时间。限流暂停表示需要重新同步，不得伪造 ACK。

新订阅初始暂停事件生成。客户端读取并验证目录和当前会话历史后，用绑定当前代次的
加密 resume 恢复；激活后再次协调权威历史，合并期间收到的事件，弥补第一次快照与
激活之间的时间缺口。恢复失败不能宣称同步完成，退避重试；其他会话在进入时读历史。

恢复始终只有一个在途任务，开始时消费待恢复标记；执行中到达的重同步请求保留为下一轮，
不能在任务完成时覆盖。多个请求合并为一次后续恢复，失败沿原有退避重试。目录基线要求
经过认证、成功读完当前快照，不要求与传输期间新到达的 catalog 版本完全一致；后续变化
仍由目录推送驱动。激活后的历史核对重新选择当前可见会话，避免恢复中切换会话造成遗漏。

离线通知是明确的低频例外：结束/需要处理时可产生受限大小的通知事件，使用既有推送
任务；不为离线授权保存流式正文、工具进度或整段输出。保留后台通知能力不意味着保存
完整离线事件流。

目录初次读取后通过加密 catalog 的 `directory_revision` 提示变化；手机在支持
`directory_push_version: 1` 的在线连接上停止每秒重复查询。Desktop 可以继续每秒
检查本地 Agent，新鲜度不要求每秒访问服务器数据库。

## 数据库预算与计数边界

所有运行时数据库消费者共用 `budgetMongoDatabase`，包括登录、配对、计费、推送、
清理和 Relay API。单服务预算为 800 单位/滚动秒，并发最多 20，等待队列最多 256，
最多等待 1500ms；超限返回可重试繁忙，不无限排队。保留额度至操作结束后再过一秒，
避免连接池等待造成后续集中发出。关闭驱动自动读写重试，应用重试重新进入预算。

普通写操作收费 1；读操作保守收费 3；游标逐批获取时再计费，不能通过一次 toArray
绕过 getMore 预算；批量操作按语句/文档数收费。每次真实 commandStarted 另计数，
只保留命令类别和时刻，不记录命令内容、命名空间或业务标识。该额度是保守准入单位，
不能拿它代替实际 MongoDB 命令速率、文档变更量、字节量、执行耗时和内存监测。

边界：这是当前一个 Node 服务进程的应用操作限额，留有至 1000 的余量。MongoDB 自身
TTL、驱动维护流量及同机其他项目不由此调度器控制；不能声称限制了整个共享 MongoDB
实例。当前线上只运行一个 Node 实例。增加实例前必须分配总量不超过预算的共享额度，
并解决跨实例在线路由和权限失效；禁止简单复制多个独立 800 限额的进程。

## 验证入口

- `tests/cipher-stream.test.mjs`：密文路由、连接代次、权限、租约、缓冲和无逐帧数据库访问。
- `tests/online-relay-transport.test.mjs`：有效订阅、独立 ACK、消费暂停、本机容量、断线恢复。
- `tests/mongo-budget.test.mjs`：滚动窗口、慢操作跨窗口、游标、队列溢出和关闭。
- `tests/online-capacity-mongo.test.mjs`：独立真实 MongoDB、100 对连接、周期重新鉴权、
  高速事件和只读往返的计数与延迟；需 `RELAY_TEST_MONGOD` 指向本机 mongod。

压测是协议/传输层和真实数据库验证，不替代真实 Agent 执行、跨网延迟或手机页面旅程。
没有生产部署前，不将本地结果描述为线上容量已经达标。
