# Relayune 功能树与公开源码、用户使用的取舍

日期：2026-10-22。依据：当前仓库源码、界面入口、命令处理和平台文档，由 Web、Desktop/Mobile、Server/Relay 三个审查分工交叉汇总。

**建议保留远程继续本机 Agent 任务的核心，优先解除官方服务绑定、补齐真实用户入口，并把运营和高级能力放到合适的位置。**
下方功能树与建议以评估时源码为依据。2026-10-22 维护者确认后，已隐藏 Web 两个只弹提示的入口；
其他改造的已确定范围、实现缺口和三端验收条件以[开源与首轮发行计划](open-source-roadmap.md)为准。
本篇最初的功能树评估只检查源码与入口，未运行应用、真实 Agent 或完整旅程；
其后已完成的构建、原生候选、合成 Agent 及生产验收以[官方联合升级清单](official-deployment.md)为准。
“源码有实现”“界面有入口”“真实环境已验收”分别说明。
项目自有部分按维护者于 2026-10-22 选择的 MIT 许可证开源；第三方部分适用各自原许可。

## 二、公开源码：真正需要删什么、改什么

### 应保留的主干

登录鉴权、每客户端独立授权、撤销、内容加密、vault、安全存储、人工审批、退出清理、资源上限和过期回收应保留。
它们支撑远程执行权限与数据隔离。不能用“只供自己用”“为了好部署”作为关闭认证、TLS、更新验签或复用内容密钥的理由。
服务端继续采用现有 Node.js + MongoDB 架构。

### 优先修改的耦合

| 范围 | 当前事实 | 建议 | 优先级 |
| --- | --- | --- | --- |
| 自托管构建 | 服务端/Web 构建同时校验官方下载文件名、更新清单和 Windows 下载提示文案 | 分开“自托管服务构建”和“官方下载站/发行校验”；使用服务不必维护作者安装包清单 | P0 |
| 服务与渠道配置 | Web API 已默认同源且可配置，Desktop 核心 server_url 也有配置；社区、法律页、更新源等仍有官方固定值 | 集中列出 API、公开站点、支持、社区、更新和推送身份配置；核心 API 与运营链接分别处理 | P0 |
| 更新和应用身份 | 官方 ID、公钥及 feed 有安装/升级兼容意义；部分开发包已隔离身份并关闭官方 updater | 在既有隔离开发入口基础上，明确官方发行与独立构建配置；独立构建不误接官方更新。保留正式验签，不批量替换既有标识 | P0 |
| 自建服务入口 | Desktop 主要依靠非秘密配置文件修改地址；Mobile 主要由编译参数覆盖 | 提供清晰的官方/自建服务选择或独立构建说明；切换服务后重新登录、配对，禁止迁移复用旧凭据 | P0 |
| 社区与支持 | 当前公开副本群码为过期占位配置；Mobile 社区请求固定到官方站点 | 社区发行默认隐藏未配置的内测群/运营入口；官方发行可以保留；不要把占位群码当有效内容 | P1 |
| 后台推送 | 无配置时服务端不初始化供应商；APNs topic、Android intent 等仍含官方身份 | 保留可选适配，补应用身份配置和不可用状态；无需推送凭据也应完成基础连接与任务操作 | P1 |
| 运维模块 | 管理员默认拒绝，SLS 已显式配置；反馈、版本观察、流量统计等不等于都随看板关闭 | 监控、反馈、版本观察、流量聚合和更新说明分别可选；说明目的、保存位置、保留范围 | P1 |
| Provider 运行范围 | Web/Mobile 默认显示三个 Agent；多适配模式仍将更多适配器加入启动集合，Pi 另有开关 | 显示偏好与实际启用范围分开；显式启用或首次使用再初始化，保留适配器扩展接口 | P1 |
| 旧协议与路径别名 | 尚有 legacy 环境入口和 API 别名；缺少当前活跃版本统计 | 定义最低版本和迁移后再废弃；不能凭名称带 legacy 就直接删 | 后续 |

此表列出的配置与渠道改造尚未实施，也不等于发现当前配置正在泄露数据。

### 可以删除或替换的内容

1. **未实现的用户入口。** Web“本地配置”和“协议文档”原先只弹 toast，现已按维护者决定隐藏。
   若仅显示 API 地址，改名为“连接信息”；若要提供帮助，打开真实文档；否则移除按钮。
2. **不能提供服务的默认运营内容。** 独立构建中未配置的内测群、占位群码、固定维护者支持入口应隐藏或替换，
   不必连同可复用的社区组件和反馈实现一起删除。
3. **确认无引用的旧商业词条和滞后文案。** 当前 Web/Server 审查未发现仍执行的 Relayune 收费门禁。
   清理语言资源中的旧订阅词条前核对引用，保留旧收费接口不再处理的回归合同。
   实时连接的 subscription、Kimi 的任务 plan、Agent 供应商额度及令牌过期都不是 Relayune 付费墙。
4. **普通用户不需要承担的维护者步骤。** 官方签名/公证/上传和运维档案放在维护者文档与显式发行命令中，
   不放进首次使用流程。发布脚本可保留，不能由普通构建或测试隐式触发。

公开域名、Team ID、应用 ID 和更新公钥本身不是秘密；此前已排除的凭据、真实用户材料和私有历史继续保持排除。

## 三、普通用户：优先改入口和状态表达

建议主线保持：**准备电脑 → 登录账户 → 安装/登录一个 Agent → 配对客户端 → 打开会话 → 发送/审批/停止**。
普通用户应能在这条路径上完成首次成功任务。

| 功能 | 建议给普通用户的表现 | 处理方式 |
| --- | --- | --- |
| 首次使用 | 清楚显示账户、Agent、系统文件权限、客户端连接各自的完成状态；明确 macOS/Windows 首次流程差异 | 修改引导，保留安全步骤 |
| Agent 选择 | Web/Mobile 沿用当前三个默认可见 Agent；Desktop 六种安装管理做同样的主次分层；显示已安装/登录/可用状态 | 保持已有默认，补能力与运行范围一致性 |
| Agent 安装与登录 | 安装按钮实际执行在线安装或全局包安装，登录会打开外部终端；说明来源、方式和下一步操作 | 保留用户点击授权，补说明；不一律增加重复确认弹窗 |
| 消息与审批 | 任务进度、最新回复、待处理审批/问题和停止操作优先；输入是否可用由真实状态与能力决定 | 保留为核心 |
| 配置与帮助按钮 | 点了能进入真实设置/文档，或者明确只是连接详情 | 删除占位或补齐真实行为 |
| Desktop 打开工作台 | 已有内部 API，但没有现成界面/托盘入口；若要方便电脑用户继续会话，可增加显式打开入口，浏览器仍独立登录和授权 | 补用户路径，不在 URL 传递桌面凭据 |
| Web 账户管理 | Web 菜单目前只有邮箱和退出；Mobile/API 已有删除账户 | 补 Web 账户管理入口，不重复实现后端或删除现有能力 |
| 多电脑 | Mobile 可管理多电脑；Web 待配对电脑选择器不等于常驻切换 | 分端说明，需求明确后补 Web 切换旅程 |
| 模型/权限/yolo 等 | 保留 Agent 返回的真实选项；高级权限与长期允许保持显式操作和既有确认 | 按需展开，不默认放宽权限 |
| 多 Agent 与会话分支 | 保留子任务查看和 Mobile 已有的按能力分支；手动并行分派无可达 UI，不能列为已完成用户功能 | 标能力边界，是否新增入口另行决定 |
| 本机网页/HTML 预览 | 在会话或附件上下文中按需出现；明确 loopback、资源类型和外部网络等限制 | 保留安全边界，不另加主导航负担 |
| 链路选择与 ACK 等 | Mobile 已默认自动选择直连/中转；普通状态显示在线/离线/重连，协议指标留在诊断 | 保留已有自动模式，收拢技术信息 |
| 防休眠/自动锁定 | macOS 按需启用，默认关闭，解释实际作用范围；不能宣传为阻止手动锁屏 | 可选系统偏好 |
| 通知与持续任务卡片 | 用户需要时开启；区分本地通知、后台供应商推送和系统挂起限制 | 保留，准确展示配置/权限状态 |
| Codex Hook | 当前连接后默认增量注册，仍需 Codex 原生信任；设置应显示注册/信任/在线状态和停用方式，或调整为按需注册 | 保留安全扩展，改可见状态；不绕过原生信任 |
| 飞书机器人连接 | 2026-10-22 维护者决定从当前开源版移除相关依赖、连接器和配置入口 | 不再列为现有或计划内功能；历史发行说明仅保留历史语境 |
| 反馈与诊断 | 明确接收方、主动附带什么，错误状态有可用重试/帮助；反馈可读，与会话密文分开说明 | 保留，改说明和部署配置 |
| 社区/宣传/下载 | 官网提供产品介绍和分发；自托管工作流不要求依赖官方群码、下载桶或测试资格 | 独立配置，未配置则隐藏 |

## 四、建议的实施顺序

1. **独立运行先闭环。** 拆分自托管与官方发行校验，明确服务器选择及重新授权，定义独立构建的更新/支持/推送配置。
2. **先修会误导点击的入口。** 修正 Web 两个 toast 按钮、过期社区默认入口、下载与平台能力描述；保留已经正确的默认三个 Agent 和自动链路。
3. **把首次任务做顺。** 用真实可用状态贯穿 Agent 安装/登录、目录权限、配对、发送、审批及停止；不依靠协议术语解释普通故障。
4. **收拢高级与运营功能。** 按需初始化 Provider；运维、第三方集成、推送与统计显式可选。保持核心主路径的独立可用性。
5. **再清理兼容与遗留。** 确认引用、最低客户端版本及迁移后，清理旧词条/环境变量/路由别名；不破坏已安装用户的授权与更新链。

后续实现应按改动选择验证。例如服务切换要验证旧凭据不复用、更新配置要验证验签与升级兼容，
而非为了做功能树先构建/安装所有平台。当前分析不增加此前敏感信息校验的范围。
